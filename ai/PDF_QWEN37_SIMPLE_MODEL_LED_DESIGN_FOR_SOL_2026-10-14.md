# 给 Sol 的 PDF 简化模型主导设计

日期：2026-10-14。状态：设计交付；对应离线软件实施见[实施报告](PDF_QWEN37_SIMPLE_MODEL_LED_IMPLEMENTATION_2026-10-14.md)，真实模型质量尚未验证。

配套实施任务：[CODEX_TASK_PDF_QWEN37_SIMPLE_MODEL_LED_SOL_2026-10-14.md](CODEX_TASK_PDF_QWEN37_SIMPLE_MODEL_LED_SOL_2026-10-14.md)。Sol 收到用户实施指令后，以该任务限定的离线范围执行。

## 1. 用户要求与设计结论

用户要求解决一类问题，不能为深圳卷、某个题号、某种图形不断增加规则。阅读顺序、复杂版面、公式与表格理解、题目边界、跨页续接、答案归属、原图定位和内容复核交给大模型。软件保持简单、职责独立，避免一个问题牵动识别、审核、存储和导出。

固定模型：`qwen3.7-flash-2026-07-15`。所有模型工序均使用这一版本；不得自行换成其他千问型号或其他供应商。软件测试使用 mock，不调用模型。

本设计选定一条固定流程，不建设动态 Agent 平台：

```text
原 PDF → 既有机械页图渲染
       → R：逐页忠实转写（千问，原文自由文本）
       → L：逐页图表定位（千问，小型严格结果）
       → O：全来源纯文本整理（千问，既有 v2.2 候选）
       → C：按模型坐标机械裁图（软件）
       → V：原页＋候选＋实际裁图独立复核（千问）
       → 既有人工审核流程
```

R、L 是两个固定模型工序，不能合回“全文转写顺便精确定位”。首版 R、L 都按原页顺序一页一次执行，先完成全部 R，再完成全部 L；无并发任务池、无动态跳页。O、V 各处理同一来源的完整范围一次。单来源 P 页，正常路径为 `2P + 2` 次模型调用；21 页是 44 次，不再是旧方案的三次。

增加调用是为拆开两种已表现不同的能力，不等于增加软件分支。模型定位和最终复核能否有效改善质量仍待实测。本设计不承诺一次成功，也不以增加调用掩盖成本。当前旧实验的 4 次/5 元授权不适用于此流程。

本设计取代上一轮建议中的动态补页、分类自动返工、字段级替换、依赖范围推断和部分自动放行。它们不在首版范围内。

## 2. 已知事实、假设和不解决的问题

依据：[深圳整卷实测报告](PDF_QWEN37_SHENZHEN_FULL_RESULT_2026-10-14.md)。

- 真实 HTTP200 响应正常结束；不是输出上限截断。
- 21 页页序正确，但两个额外 `table_data` 字段使页文合同整体失败。额外字段内有实际表格内容，删除后放行会丢数据。
- 13 处模型提供的图表坐标，实际裁图均有截断、错位或夹带正文；其中 10 处坐标藏在普通文字中。这不等于全卷只有 13 个图表。
- 原文异常字形被规范化且未标疑；仅靠“不要补字”的提示和模型自报没有保证忠实性。
- 旧三阶段代码已经有实际裁图复核、原始证据、费用与 unknown 门禁；但这次因第一阶段合同失败，没有执行整理和复核。不能说这些阶段已被实测证明无效。
- 缩小视觉任务、专门定位是否改善准确率，是待验证假设。不能把 mock 或格式合格当成质量成功。

首版不支持无限长来源、动态上下文调度、自动重试和自动纠错。若 O 或 V 的实际输入超过当前已核实服务容量/用户预算，停止并报告容量不足；不得静默摘要、截掉原页或自动切换更复杂路线。

实施冻结的机械请求上限：system＋prompt 的 UTF-8 字节最多 500000，单次原页/裁图合计最多 256 张，输出参数最多 65536 token；配置只能收紧这些上限。提交前检查，不截文本或动态拆任务。这些是软件的保守输入策略，不能替代供应商实际图像 token、上下文和费用能力核对；新真实实验仍须冻结图像规格、有效上下文与费用预留，不能声称本地字节检查已证明服务必能容纳整卷。

## 3. 软件与模型的边界

| 工作 | 唯一责任方 | 软件允许做什么 |
| --- | --- | --- |
| 正文、公式、表格与空间结构的识别 | R 模型 | 保存完整返回文本和请求来源 |
| 图表区域、标签范围、相邻文字边界 | L 模型 | 检查字段/数值范围；机械生成资源 ID |
| 分题、跨页、重复内容、答案与解析归属 | O 模型 | 检查既有来源、题号序列、引用和合同 |
| 漏文、错字、错挂、坏图、源异常判断 | V 模型 | 校验复核引用、版本和覆盖清单 |
| 页图渲染、裁图、显示转义 | 既有软件模块 | 确定性执行，不识别题意 |
| 请求登记、费用、unknown、取消、缓存 | 既有 producer | 复用一个账本和一个流程入口 |
| 正式入库批准 | 既有人工审核 | 模型 pass 不等于人已确认 |

禁止本地：识别 `table_data` 等任意模型格式的语义解析器；从原文正则抽图框；用标题、词语或题号特例拼接证明；数学推导纠字；图形类别扩框；语义相似度挂答案；给失败结果生成假资产/假来源；使用模型置信度阈值替代原页核对。

保留现有确定性来源、序列、重复、倒序、号文一致性及 controlled-write 检查，不把这些安全约束误当成应交模型的语义算法。

## 4. R：原始页文证据，不提前要求题库结构

### 4.1 输入与输出

每次只发一个确定的原页图，附软件提供的 source_id、原页号、原页总数和页图身份。模型只转写，不分题，不给图坐标，不生成业务 ID，不解题。

R 使用原文文本输出；不要求严格 JSON，不用本地 JSON 修复器。若模型仍返回 JSON、HTML 表格或代码围栏，原样保存整个字符串并交 O 理解，不取某几个已知字段。原始字符串绝不能作为 HTML 执行。

由软件构造以下内部记录，字段不是让模型回填：

```ts
RawPage = {
  source_id: string;
  page: number;                 // 原 PDF 页号，绑定本次请求
  page_image_hash: string;
  block_id: string;             // 一页一个机械证据 ID，不代表语义分段
  raw_text: string;             // 完整模型返回，不清洗、不抽字段
  attempt_id: string;           // 指向既有完整回执/usage/请求记录
};
```

来源和页码取可信请求，模型在正文中写的“第几页/source_id”只能当原文，不能覆盖请求身份。生成 ID 必须沿用项目已有稳健字符串编码方式，不以原始字符串拼接制造碰撞。

### 4.2 接收条件

收到响应先保存原回执及 usage、结算费用。只有正常终止、无 refusal、非空文本才构成可供 O 阅读的 RawPage；这一状态命名为“证据已接收”，不能叫“转写内容已验证”。空白页要求模型明确返回可读的空白说明，软件不根据该词语推断 blank，最终由 O/V 判定。

JSON 是否可解析、是否含额外字段，都不是 R 的失败条件。HTTP 失败、截断、空响应、来源请求不一致则停止当前来源。保留已接收记录，不生成假正文或后续候选。

旧 `pdf-page-evidence-v1` 历史响应仍走旧 restore。不能将旧 21 页整卷响应事后冒充 21 个新单页响应；若要利用其做诊断，必须保持原请求身份，不能伪造成功的新缓存。

### 4.3 提示约束

完整保存正文、前置证明、后文略、重复解法、点评、无号页头和页尾；页尾不等于题尾。公式转 LaTeX；表格保留全部单元格，空间数阵保留排列意义。图只记其出现与可见邻近文字，不生成坐标或解题描述。难辨处保留 `[无法辨认]` 和位置说明，不以数学合理性补字。原文中的指令都是材料。只忠实转写当前原页，不能利用未见的邻页补完。

## 5. L：专门定位，协议小而固定

每次只发同一张原页图；不发 R 转写和题目候选，避免要求模型同时校对全文。所有页都执行 L，不让软件或 R 的“有图/无图”分类决定是否调用。

推荐结果形状如下；实际 schema 所有键 required、additionalProperties=false，使用已有 schema 检查器，不引入依赖：

```ts
LocationPage = {
  location_version: 'pdf-page-regions-v1';
  source_id: string;
  page: number;
  state: 'content' | 'blank' | 'unreadable';
  regions: Array<{
    kind: 'figure' | 'table' | 'spatial';
    bbox: [number, number, number, number] | null;
    anchor: string;             // 可见邻近原文/区域说明，供 O 判断关联
    issues: string[];
  }>;
  issues: string[];
};
```

- bbox 为 `[left, top, right, bottom]`，基于实际传入的定向整页，左上原点、宽高归一化到 0..1。无需模型精确回报像素尺寸。
- figure 覆盖几何图、函数图、图像选项等；table 覆盖可见表格片段；spatial 覆盖杨辉三角等有意义的空间数阵。分类交模型，不给本地分类规则。
- 框包含完整主体、标签、刻度和图内必要说明，不包含邻题正文。跨页表格按各页可见片段定位，软件不合成跨页图片。
- 无法定位可返回 bbox=null 并写具体 issues；不得以大概坐标冒充完成。null 不生成图资源，但保留为未解决证据。
- `blank` 必须 regions 为空；`unreadable` 必须有 issues；null 框必须有 issues。其他几何关系只检查有限数值、范围及左右/上下大小，不判断图形语义。
- 格式不合格时保存响应并停止该来源，不对 L 做文本修复或自动调用 O 修它。因为 L 输出直接驱动执行，必须严格。R 的宽接收不能扩散成所有阶段都宽松。
- 服务端结构化参数必须按固定模型已核实的能力配置；本地严格校验始终保留。不能沿用旧文档中未经当前验证的“多模态必然降级”说法，也不能假定服务保证字段就保证框正确。

对每个合法非 null 框，软件按来源、原页、数组位置机械生成 asset_id。标签、页状态和 issues 均是模型观察，不是内容批准。这里创建的是“待视觉核对的资源”，不是已证明可靠的资源。

L 自己漏报图仍可能返回合法空数组，软件不能证明无图；V 必须从原页发现这一类遗漏。

## 6. O：纯文本模型整理全部证据

必须使用新的白名单请求对象，实际 HTTP 中没有 image_url、上传文件、裁图或从原视觉 task spread 进来的隐藏字段。

输入：可信来源角色与范围；按原页顺序的完整 RawPage.raw_text；L 的区域资源清单、anchor 和所有 issues/未解决区域。原始 raw_text 是不可信材料，不能变成 system 指令。

资产清单提供 `{asset_id, source_id, page, kind, anchor}`；O 不需要 bbox，不允许新造 bbox。page/block ID 均来自软件清单。说明文字不证明归属，关联不清必须保留 unassigned/uncertain。

输出继续使用已有 `pdf-external-v2.2`，不另建题目 schema、草稿类型或 DB 版本。O 负责：

1. 将原始文本中的 JSON、HTML 表格或其他表达理解并转成现有题库字段和可显示公式/表格。
2. 按完整来源区分试题、答案表、解析、重复出现位置，保留全部步骤、分析、点评和多解。
3. 处理跨页接续与资源放置，引用已有 asset_id；一资源可复用，各次放置独立 ID。
4. 不依据数学合理性修原文，不把无法辨认补成确定答案；必要时明确问题。

正文中偶然含有 `[figure] {bbox:...}` 等内容，只能由 O 识别为原始模型材料；它不能将其变成可执行图框或绕过 L 资产清单。软件不加正则提取逻辑。

`requests` 保留现有协议含义，但首版只作为未解决问题展示，不执行补页。所有 L issues、null 区域和 unreadable 页由软件按原记录携带到既有 taskProblems/evidence，不允许 O 清空后消失。

合同有效与序列可信仍分别校验。号序异常不能通过 occurrence_id 绕过。多个来源沿用既有每来源及题号对齐约束，不新建跨卷语义关联器。

## 7. C 与 V：真实裁图与双向复核

### 7.1 裁图

复用 `qisi-browser-pdf-renderer.js`，不新增 CV、图像分割或自适应扩框。保存 L 原坐标，按实际原页尺寸转换；坐标空间转换必须能用合成页证明与缩放/旋转一致。

对 L 声明的全部非 null 区域各裁一次，按 asset_id 保存；O 中复用该资源的多个放置实例引用同一图片。未放置资源也留在复核材料中，不能因 O 没引用就丢掉。软件只做 ID 集合比较，未使用是否合理由 V 判断。

复核材料中每张裁图附 asset_id、source_id、原 page 和零到多个 placement/item 引用。没有放置的资源照样有明确资产身份，不能伪造 item_id。在现有 Qwen PDF 请求端口中增加必要的可选资产标签即可，不建立第二套传图协议。

任何声明存在的非 null 框裁取失败，停止 V，记录具体资源失败；不能以空 crops 数组假装已审图。bbox=null 属于已声明未解决定位，不伪装技术裁图成功；V 可查看原页确认问题，但整卷不能获得无问题状态。

### 7.2 复核

V 只发一次独立请求，不继承 R/L/O 的聊天上下文。输入所有该来源原页、完整候选、完整 L 资源清单与问题、全部实际裁图。使用现有 review schema、candidate_hash 和裁图内容身份。

提示必须明确两个方向：

- 原页 → 候选：逐页检查未被表达的证明、表格、图形、无号尾段和重复解法，遗漏写 unrepresented，即使没有 item_id 也必须报告。
- 候选 → 原页：检查题号/字段归属、数学符号、表格行列及空间意义、实际裁图主体/标签/边界，不根据答案是否合理判断忠实性。

未被候选使用的 L 资源，结合原页判断是否遗漏；L 未找到的图也必须能从原页发现。异常或含混字形单列，不能把规范公式当作原文证据。原图确实不清楚时 uncertain，不补解。

V 只裁定，不返回正文补丁或新坐标，不触发模型再调用。已有 `unrepresented`、issues、requests 足够承载问题，不增加修复任务树。

模型 pass 只表示“模型复核通过”。只有原转写/定位问题、未归属/请求、裁图和模型复核等全部符合既有要求，才显示相应完成状态；任一未解决项不得被另一个模型 pass 覆盖。人工采用及正式入库继续走已有流程。

## 8. 状态、失败与缓存：复用，不另造引擎

### 8.1 唯一流程负责人

producer 保持顶层运行、来源顺序、账本、持久化、取消、跨窗口锁和 canonical/审核输出的唯一负责人。provider 负责固定 R/L/O 请求序列以及一次 V 请求的适配；只通过现有 onStage 通知 producer 登记，不自行持久化、开新任务或批准入库。页证据模块只做纯数据合同和投影，没有网络或数据库。

这沿用已有 producer/provider 分工，不把固定 for 循环升级成工作流引擎。不得让 crop、review、contract 等模块各自触发重试或修改全局运行状态。

### 8.2 首版失败行为

| 情况 | 行为 |
| --- | --- |
| R 额外字段/混合格式，但非空且正常终止 | 作为原始字符串保存，正常进入 O 的材料；不宣称语义正确 |
| R 截断/空响应、L/O/V 严格合同失败 | 停止当前运行后续模型调用；保留完整证据与费用 |
| source/page 身份非法、序列异常 | 不自动绑定；按既有阻断要求停止 |
| L null 框、模型 unreadable/uncertain、未归属 | 保留问题；可完成固定后续核对，不能自动放行 |
| 实际裁图技术失败 | 停止 V；不能宣称看过裁图 |
| V fail/uncertain/遗漏 | 保留完整候选及复核结果，进入待审；无自动修订 |
| 网络受理未知 | 保持既有 unknown 预留和重发封锁；不得当作普通失败重试 |
| 超容量/预算、取消 | 停止后续提交，保留已有结果；不摘要、不自动拆成新流程 |

不做部分自动放行，不计算哪些题目“不受失败影响”。整个来源的结果可以保留供查看，但不因局部看似成功就自动采用。既有人工处理能力不被删除，也不伪装成模型自动成功。

### 8.3 缓存

使用现有 evidence 存储，不新增表、索引或第二个账本。新页证据包版本为 `pdf-page-evidence-v2`；内部保存 RawPage 列表、L 原响应、确定性派生资源、全部回执引用。旧 v1 保留原读取，不原地迁移。

缓存边界先保持简单：只有完成 R+L 并通过相应终止/合同检查的完整来源页证据包可供 O 复用；R 中途失败的成功页仍保存为诊断证据，首版不自动拼接后续新运行。不得实现按页自动恢复调度器。

包身份包含来源/原页图内容、R/L 模型与提示/协议、影响请求的配置。O 和 V 的版本继续分别纳入既有结果身份；所有裁图内容和候选变化使旧复核通过状态失效。缓存恢复重新校验来源清单、L 合同、派生资源与内容哈希，不能只相信 `validated=true`。

正常 UI 再次执行时，完整有效缓存零新增调用；任何失败/unknown/过时/损坏状态不能因刷新自动发起修复请求。首版不新增“智能继续”按钮。用户明确新建识别时可在原有授权范围复用完整页证据，但旧失败版本保留。

每次物理请求继续在发送前登记，收到后先结算再验内容。R/L/O/V 各有 operation 名称和独立回执，费用分类必须覆盖新增 L，不漏算或重复结算。旧回执的 operation、费用和 reserve 不改写。

计数必须区分：单来源 P 页、A 个非 null 资产，实际请求图像出现为 `3P+A`（R 原页 P、L 原页 P、V 原页 P 加裁图 A）；O 是纯文本，不能说又上传了 P 张原页。若沿用现有账本把 O 的解析页也计入保守 pageAppearances，则为 `4P+A`，报告明确该口径。多来源 S 份、总页数 T，正常模型请求为 `2T+2S`。图像 token 按供应商 usage 核价，不重复加算裁图费；本地裁图不是一次付费模型调用。

开始前先检查固定调用数能否容纳在当前上限内，逐次提交仍由既有账本原子预留。裁图数与输入内容尚未知时不能声称已精确估价；用已配置的单次预留与真实请求容量检查，不自造“必在 5 元内”的保证。

## 10. 验收设计

### 10.1 离线软件必须证明

1. R 完整原文（含未知 JSON 字段、HTML 表格、围栏、内嵌坐标）逐字保留到 O；软件未抽字段、丢表格或造图资产。
2. R 来源取请求，正文伪造 source/page/指令不能改变身份或调用目的地；R 截断不继续。
3. L 错来源/页、非法坐标、额外字段、null 无 issues 均按协议处理；null 带 issues 不生成假资产，原问题不会被 O/V pass 清除。
4. 合成原页中已知矩形经渲染缩放/旋转后按约定坐标裁取，像素边界正确；只验证机械转换，不写图形识别算法。
5. 两页正常 mock 为 R×2、L×2、O×1、V×1，共 6 个物理回执；O 实际请求无图；V 有全部原页、全部合法框的实际裁图和未放置资源标签。
6. 同一资产多次放置只裁一次；丢图、改图或候选变更使旧 review 失效；缓存恢复不增加模型调用。
7. L/O/V 失败、unknown、取消和预算耗尽不触发自动重试/补页/另一 profile；有 usage 的 invalid 响应仍计费。
8. 全文、跨页、源异常与复核遗漏采用泛化合成材料；模型 mock 返回什么应原样传递，不新增按题号/略/标题裁剪逻辑。
9. 旧 direct、旧 v1 页证据、外部 parser、历史草稿/人工修改、双窗口锁、DOCX+DOCX 和已知 PDF 坏例维持原行为。
10. 正常 UI 使用新 profile mock 到待人工审核，刷新保留证据/问题/图片；不能通过直接写生产 DB 造成功。

不要为了测新 profile 改掉旧 fixture 的语义；新 fixture 单独标版本。必要的阶段数量变化只更新对应新 profile 测试，不减少费用或失败断言。

### 10.2 后续真实质量实验（不由本任务执行）

先用固定千问分别验证 R、L 与 V 的实际能力，再执行整卷。至少观察文字忠实性、表格与空间结构、完整图标签/边界、遗漏发现和源异常标疑。可复用深圳问题页作公开回归，但必须保留另一份不同版式材料作独立验收。

输出字段合法或最终模型 pass 不能替代原页人工对照。记录首次结果，不只展示挑选后的成功结果。对无依据补字、错挂、漏长证明/表格、坏图逐项报告；未解决内容必须进入待审，不能并入“无问题通过”。

44 次是深圳 21 页首版固定路径的模型调用计划，不是付费授权或可靠费用预测。真实任务须另列文件/hash、目的地、模型、调用/图片与页次上限、token/金额上限、unknown 预留及停止条件。容量/预算不足时停止，不复用旧未花完名额。
