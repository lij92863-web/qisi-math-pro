# 双 PDF 对齐：从"位置身份"到"锚定键身份"

> 本文只论证一个纯函数级别的替换：PDF 外部识别链（pdf-external-v2）中，
> 支持流（答案/解析）与试题流的对齐判定。**不修改** DOCX 链与
> `qisi-pdf-support-aligner.js` 共用的稳定链 B 规则。

## 1. 问题形式化

设试题流给出的题号序列

    E = (e₁ < e₂ < … < e_m)

支持流（答案或解析）给出的题号序列

    A = (a₁ < a₂ < … < a_n)

`sequenceOf` 已保证两者都是严格递增的正整数序列（否则直接 fail-closed）。
真正要判的是：A 中的第 i 项，是否可以被信任为"第 aᵢ 题的答案/解析"。

现行规则（单流分支）：**前缀判定**

    accept(A) ⇔ n ≤ m 且 ∀i ≤ n: aᵢ = eᵢ

## 2. 现行规则的问题（不完备，不是不安全）

取 E = (1,2,3,4,5)，A = (1,2,4,5)（第 3 题答案在原卷上缺失）：

    前缀在第 3 位断开 → 只接受 {1,2}，第 4、5 题被拒

这**不是**识别错误，而是判定规则把"中间缺一项"误判成"整体不可信"。
在真实答案卷里，"某题只在解析中给出""解析跨页且续页无号"都会产生这类洞。
洞的出现是**局部**信息缺失，而前缀判定是**全局**否定——两者的粒度不匹配。

## 3. 关键不可区分性（为什么不能简单改成按题号挂）

只看 A 和 E 时，下面两个世界产生**完全相同**的观测：

- W₁（头部缺项）：真实答案是 1..5，但第 1 题答案在原卷中缺失 → A = (2,3,4,5)
- W₂（整体错位）：该答案文件实际属于编号 2..6 的另一份卷子（或整卷错位 +1）→ A = (2,3,4,5)

因此：

> **命题 1（不可区分性）** 仅由 A 与 E 决定的任何判定函数，在 W₁ 与 W₂ 上输出相同。
> 故不存在"既安全（W₂ 不误挂）又完备（W₁ 不全拒）"的纯机械规则。

这条命题解释了为什么旧规则选择"安全但不完备"——它是**在没有额外信息时的唯一正确选择**。
问题出在：新链路里其实存在额外信息（模型对原页的观察），而旧规则没有用它。

## 4. 锚定键连接（本文提出的规则）

引入一个可观测的**锚位**：支持流的首项是否就是试题流的首项。

    anchored(A) ⇔ a₁ = e₁

判定：

    accept(aᵢ) ⇔ anchored(A) 且 aᵢ ∈ E

即：锚位成立时，按**题号**做连接，允许中间任意跳号；锚位不成立时，全部拒绝。

### 命题 2（安全性）

对任意 δ ≠ 0 的整体错位世界，A 的首项为 e₁+δ ≠ e₁，`anchored` 为假，全部拒绝。
对 δ = 0 的世界，被接受的 aᵢ 满足 aᵢ ∈ E，按题号连接即为恒等映射，不产生错挂。∎

### 命题 3（在锚位可用时的完备性）

δ = 0 且 a₁ = e₁ 时，A 中任一存在项都满足 aᵢ ∈ E，故全部被接受；
不存在"原卷上确有该项却被拒绝"的情形。∎

### 命题 4（锚位的必要性）

由命题 1，去掉锚位后 W₁ 与 W₂ 不可区分：
接受两者 ⇒ 在 W₂ 中错挂；拒绝两者 ⇒ 在 W₁ 中丢失。
锚位恰好把判定推向 W₁（接受），并在 W₂ 中拒绝——因为它利用了 W₂ 中 a₁ ≠ e₁ 这一**可观测差异**。∎

### 结论

在"仅有题号序列"的信息集下，**锚定键连接是唯一同时满足安全性与最大完备性的规则**：
它把旧规则牺牲掉的中间项全部救回，同时保留对整体错位的拦截。
代价是"首项缺失"的情形仍然 fail-closed——这是命题 1 决定的，不是实现缺陷。

## 5. 完备性的剩余缺口与它的补齐方式

| 情形 | 现规则 | 锚定键连接 |
| --- | --- | --- |
| 完整覆盖 1..m | 接受 | 接受（mode=full） |
| 从头连续、尾部缺失 | 接受前段 | 接受前段（mode=prefix） |
| 中间跳号 | **整段放弃** | 按题号接受（mode=gapped） |
| 首项缺失 | 全拒 | 全拒（安全侧） |
| 整体错位 ±δ | 全拒 | 全拒（锚位拦截） |
| 拿错文件 | 大概率全拒 | 全拒（锚位拦截） |

"首项缺失"与"拿错文件"在纯题号层面不可区分（命题 1）。补齐它们靠的是**语义证据**，
而不是再加机械规则：把试题的「题号 + 题型 + 题干首句」传给支持流的整理阶段，
由模型对照原页判断归属；软件只做键校验，不做语义猜测。

## 6. 影响面

- 改动：`qisi-pdf-external-contract.js` 的 `evaluateSequences`（单流与双流分支）。
- 不改：`qisi-pdf-support-aligner.js`（DOCX 与旧 PDF 支持链共用，属稳定链 B）。
- 需同步：`qisi-import-validation-service.js` 对 mode 的白名单（新增 `gapped`）。
- 不变式：`sequenceOf` 的严格递增、来源一致性、`unmatched` 兜底、失败即停原则均保留。
