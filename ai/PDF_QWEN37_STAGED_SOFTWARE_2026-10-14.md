## 类别问题与通用职责分配

前次单次视觉请求同时承担全文保全、阅读顺序、分题与跨页、答案归属、公式表格、资源定位、引用命名及字段输出。现在分别调用模型，减少一次任务中的职责混杂。模型继续负责语义理解和忠实识别；软件不按特定题号、标题或“略”字串补证明，不按数学合理性改字，不按题意猜归属。

| 阶段 | 模型负责 | 软件负责 |
| --- | --- | --- |
| 原页全文转写 | 所有输入页的阅读顺序、全文及重复内容、长证明、多解、公式表格、无号页头页尾、原图位置和源异常 | 校验页来源/顺序/状态和字段形状，保留原回执，机械生成块与资源 ID |
| 纯文本整理 | 根据全文及可信输出范围理解分题、跨页、字段归属、完整步骤和资源放置；无法判断则标疑/保留 unassigned | 显式传入块/资源清单，检查合同和序列；不发送图片，不从模型失误自动切换流程 |
| 独立视觉复核 | 逐页对照原页和真实裁图，检查遗漏、归属、源符号、证明、表格及图标签/边缘/邻题 | 先按模型框取得图像，再发独立请求；保存候选及裁图版本，复核失效则阻止复用通过状态 |

独立复核是一次单独请求，不继承转写聊天上下文。固定使用同一模型的实际效果仍需原材料验证；mock 通过只证明软件合同、状态与持久化行为。模型的 `observed_complete` 继续只是观察声明，不是正式入库批准。老师仍需核对来源、采用字段候选并确认图片/问题后，才能完成原有审核。

## 已实现的软件边界

1. 新增纯页文模块 [qisi-pdf-page-evidence.js](C:/Users/Administrator/Desktop/题库系统/qisi-pdf-page-evidence.js)。转写提示只提供输入页，取消分题和输出范围筛选职责。原文文字不经本地语义清洗；块、资源编号由软件机械生成，支持任意来源字符串。缺页、重复/倒序/其他来源、伪空白页、非法坐标、截断响应拒绝继续整理。转写标疑保留具体页和块；全局标疑不伪造页号。
2. [provider](C:/Users/Administrator/Desktop/题库系统/qisi-pdf-external-provider.js) 显式绑定三个模型阶段，保留旧 direct 和外部 parser 接口。纯文本请求通过白名单对象组装，携带 `json_schema` 请求约束，不携带图像、文件或旧上传任务。模型只能引用软件给出的 block/asset 清单；资源身份可复用，每次正文放置使用独立实例 ID。
3. [producer](C:/Users/Administrator/Desktop/题库系统/qisi-pdf-external-producer.js) 在模型请求开始前登记每个物理调用，保存实际 prompt/schema/输入哈希和原始响应。收到但合同无效的响应仍登记用量费用；受理未知状态继续封锁自动重发。原页缓存身份与整理/复核 profile 分开：修改整理 profile 可以复用完整原页转写，修改转写模型/提示/协议则失效。缓存恢复重新从保存的原回执投影，不能静默接受篡改后的页文、块或资源表。
4. 原图资源先于复核解析。新页文资源按模型原 bbox 本地裁取，不增加付费 resource 请求；外部 parser 的资源请求仍逐次记账。复核同时收到整页与实际裁图，标签含 item、placement、source、page 和 field。裁图版本纳入复核缓存；图像字节改变或消失后，旧通过状态失效，不自动追加付费复核。
5. 转写标疑进入候选证据和审核面板，保留“原页转写标疑”来源；任务问题继续要求老师核对。全局标疑没有虚假的“第 null 页”链接。模型复核通过不消除原转写标疑，不自动确认或入库。
6. [配置](C:/Users/Administrator/Desktop/题库系统/qisi-config.js) 固定三阶段模型、关闭默认启用，并配置三阶段各自费用估算。阶梯复用同日核对的[阿里云官方价目](https://help.aliyun.com/zh/model-studio/model-pricing)：按输入 token 档位核算，图像 token 不重复加算。测试中的费用是 mock 用量的计算结果，不是新产生的供应商账单。

页次数预算继续保守计算输入页/解析页，加上复核实际裁图数量；纯文本整理页次数不表示又上传了原页图片。正常的新本地裁图管线每个任务是三次模型请求，三份独立回执；额外查询/外部资源仍分别计算。没有自动补页、修订、重试或自动模型降级。

## 浏览器发现并修复的通用问题

- direct 模式配置中存在闲置的 parser 绑定时，错误地套用页文缓存校验。现按实际执行模式选择 parser profile；历史直接识别不要求不存在的转写缓存。
- 实际裁图模块只返回图片字节，没有回传 bbox 时，模型给出的合法原页坐标丢失，导致 canonical 图片门禁拒绝。现直接保留已经验证的资源原坐标；没有调整、扩框或猜测图形。
- 所有实际裁图均不可用时，不能以“裁图数组为空”绕过旧复核版本检查。现同时检查裁图错误和裁图版本，保持失败关闭。

这些修复均有反例验证。浏览器初次/诊断失败日志保留在本轮证据目录，没有降低原有成功断言。
