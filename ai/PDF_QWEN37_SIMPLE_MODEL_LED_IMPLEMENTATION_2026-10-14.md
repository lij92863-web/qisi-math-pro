## 实际流程

新内部 profile 为 `qwen37-simple-model-led-v1`，只支持完整连续原卷的 document 范围。先顺序执行每页 R，再执行每页 L，最后每来源一次 O 和 V：

| 工序 | 模型/软件的实际职责 | 输出边界 |
| --- | --- | --- |
| R 原页转写 | 千问忠实转写全部文字、公式、表格、证明和重复内容 | 完整原始字符串；不解析额外 JSON 字段/HTML/内嵌坐标 |
| L 原页定位 | 千问专门给全部图表/空间数阵区域及不确定问题 | 小型严格合同；软件仅验证身份/字段/坐标与生成 ID |
| O 纯文本整理 | 千问理解全来源、跨页、题号/字段归属与表格表达 | 既有 v2.2；实际请求没有原页或裁图，不能创造 bbox |
| C 原图裁取 | 既有软件按 L 的原框机械执行 | 每资产一次，未放置资产也裁取；不扩框、不做视觉分类 |
| V 独立核对 | 千问从原页查遗漏、从候选查依据，核对所有实际裁图 | 既有 review 协议，只裁定，不修补、不触发后续模型调用 |

P 页正常模型请求是 `2P+2`；两个来源总页数 T 时为 `2T+4`。21 页深圳卷的新正常路径为 44 次，这只是未来计划，本轮没有执行这些请求。O 虽被现有保守页次口径计入解析页，实际没有发送图片。

## 如何限制复杂度与耦合

没有新增业务模块、DB/schema、供应商、工作流引擎、动态补页、重试器、语义解析器、字段补丁合并或局部自动放行。

- page-evidence owner 只新增 v2 纯合同和机械投影，保留 v1 原读取。每个 raw 页的来源/页号由请求绑定，正文伪造身份不会替换它。
- provider 只适配固定 R/L/O/V 调用，仍经既有登记回调，不另行持久化或决定入库。R 返回自由文本；L、O、V 各按对应合同检查。
- producer 继续作为唯一账本、缓存、取消、资源与审核投影负责人。没有本地分题、表格理解、数学纠错或图形判断。
- canonical 与人工审核继续使用原协议和门禁。转写/定位问题不会被 O/V 的 pass 清掉；模型 pass 不等于人工确认。

六个业务 owner 的有界变化：

1. `qisi-pdf-page-evidence.js`：v2 RawPage/LocationPage、原页图身份、资源机械 ID、完整包恢复；仅 L 合法框能生成资产。
2. `qisi-pdf-external-provider.js`：固定单页 R/L 和全来源 O；V 追加双向核对及定位材料；纯文本请求白名单。
3. `qisi-pdf-external-producer.js`：按物理 attempt 记 R/L 费用，完整来源缓存、全部资源裁图、失败停止与取消状态；复用既有序列检查。
4. `qisi-pdf-external-contract.js`：定位问题显示“原页定位标疑”，其余 wire/review 和正式准入标准不变。
5. `qisi-qwen-vision-source-port.js`：PDF 裁图标签可包含资产与零到多个放置实例；R 可使用显式 text 格式。DOCX 请求职责未改。
6. `qisi-config.js`：指定关闭状态下的新 profile、固定模型及机械请求上限。

没有改 app.js、main.html、app.css、架构/加载注册、DOCX、正式入库策略、依赖、凭据或生产服务。

## 证据、失败与费用

R 的未知字段、表格尾行、HTML 与内嵌 bbox 全部原样进入 O 的材料。软件不删 `table_data`、不从原文抽坐标、不把模型材料当可执行 HTML。

收到每次响应先保存回执和 usage，再检查内容。转写截断、严格定位/整理失败、题号序列异常，会停止后续请求并保留费用；模型要求补页只显示问题。定位 null 框不会制造资产，仍携带问题给后续固定核对。

L/O/V 的格式失败和裁图技术失败不触发自动修复。已失败/取消的相同配置不能通过重跑自动提交；复核 pending/invalid 即使来自缓存，也阻断后续来源请求。V 的内容 fail/uncertain 保留待审候选，不做模型补丁。

取消时，已有完整回执仍是 received 且保留已知费用，未完成任务标 cancelled。若存在 registered/submission_unknown 的物理请求，继续保留 unknown 状态与预留，不假设取消免计费。

完整来源 R+L 是可复用的页证据包，中途成功页仅保存为证据，不自动拼装重试。包恢复重新核对原响应、页序、派生资源及身份。整理配置变化可以复用完整页证据，旧版本保留；候选或实际裁图改变使旧复核 pass 失效。

R/L 的 parserCost 现在按所有物理回执求和，不再只取最后一个请求；其他费用也按各自工序汇总。unknown 和 invalid 的收费记录不丢失。测试中的 usage/价格计算都是模拟证据，不是新供应商账单。

机械容量策略在提交前检查：system＋prompt 最多 500000 UTF-8 字节，最多 256 张原页/裁图，输出参数不超过 65536 token；可收紧，不动态摘要/拆分。图像 token、实际供应商上下文和金额预留仍需新真实任务冻结，本地字节检查不证明供应商必可受理整卷。
