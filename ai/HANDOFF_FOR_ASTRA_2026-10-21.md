`qisi-draft-editor-service.js` 在当前目录不存在，不能因为旧任务文件提过就视为已实现。`qisi-review-view-model.js`/`qisi-ui-renderer.js` 的现有接口很小，不能未经核对直接当成完整审核模块。`qisi-handout-html.js` 虽已有 buildHtml/escapeHtml，但当前页面未加载且其输入是另一套讲义区块，复用前需比较契约，不强行套用。

### 17.2 状态归属与数据流

- **持久化真值**：草稿、批次、正式题、图片及版本在现有存储层；页面数组是读回投影，不是另一份准入真值。
- **审核页面状态**：当前批次、当前题、编辑缓冲/原值、选中集合、筛选、弹窗归同一个审核页面实例。初期仍留现有 refs，先提取计算；随后按小步骤迁移，禁止新旧两套 refs 双写。
- **导入运行状态**：交给已有 controller/任务服务。页面 loading 仅展示，不代替运行锁、幂等和取消信号。
- **组卷状态**：题目 ID 顺序、分值、分组、模板与偏好有一套 owner；题目内容仍从题库读取。不得为打印创建第二套可变试卷车。
- **资源状态**：正式题图 object URL、草稿来源图、裁剪临时图、打印窗口资源分别明确创建者、消费者、释放时点；只有确定生命周期后才决定是否需要新的聚焦资源模块。
- **原始证据**：源身份、原文、页号、块位置、缓存身份留在原合同；显示清洗输出是派生值。

目标数据流：用户事件 → 页面参数/状态 → 现有领域服务 → 现有受控持久化 → 读回 → 只读显示。纯显示/文档生成函数不访问数据库、localStorage、全局 Vue proxy 或识别端点。

### 17.3 接口设计规则

1. 输入显式列出，返回值区分成功、拒绝及诊断；保留现有错误码和警告语义。是否继续采用当前抛错方式由现有契约决定，不统一包一层 catch。
2. 不传整个 App、整个 Qisi 全局或含几十个无关字段的 context 来伪装解耦。仅注入实际使用的端口；工厂装配依赖和每次命令参数分开。
3. 模块不回调 app 私有函数形成环；必要的 UI 回调只负责通知/定位/刷新，不偷偷做校验、写库或换路线。
4. 保留当前浏览器和 Node 导出模式，不同时做 ESM/构建系统迁移；新增加载项必须先于消费者且恰好一次。
5. 优先扩展已有同责模块。确需新模块时在任务卡中说明为何现有 owner 容不下，并限制单一职责，不建新的大杂烩。
6. 行数只作附带统计。真正验收的是职责、可变状态、调用边界、生产接线和旧入口退出。

## 18. app.js 分步迁移任务卡

所有阶段开始前：工作区基线已明确；本阶段任务卡列准确函数/文件；已有验证可运行；先写必要的当前行为保护，再迁移接线。下列“候选文件”是规划，不是对全部文件的批量修改授权。新模块名字和准确白名单在相应阶段封口，不能先写代码再补说明。

### R1：审核只读投影，先完成一个无写入切片

**用户结果**：打开同一批次看到相同题数、缺项、筛选结果、编辑预览、题图与原页图。

拆成 R1a 统计/筛选，R1b 图片显示分类，R1c 编辑源只读预览；每一步单独验证。函数定位：batchRecognitionSummary、filteredDraftQuestions、activeDraftImages/RealQuestionImages/SourcePageImages/PreviewImages、buildDraftEditorSource、buildDraftEditorProjection。各步只选自己的函数，不一次搬整段。

候选文件：app.js 对应计算与调用；qisi-review-draft-state.js、qisi-question-image-policy.js 或经论证的新只读投影模块；相应单元/E2E 测试；若新增模块则 main.html 和准确架构登记。PDF 合同只作为依赖，原有绑定和准入逻辑不改。

接口草案：统计输入 drafts 与明确 helper，返回 totals/missing 列表；图片投影输入一题、该批图片及合同读取端口，返回显示列表；编辑预览输入 source 与 question，返回 stem/options/type/parsedOptions。返回的是展示，不反写原题，也不生成虚构来源。

验收：空批次、无答案/无解析、零/四/不完整选项、重复图片 ID、无效图、原页图与题图分离、DOCX/PDF 不同协议、输入对象不被改变。普通 UI 对比筛选与编辑预览；选中题、焦点和未保存内容不变。归属规则不趁机优化；现有差异先保留并记录。

退出：每迁出一个函数就删除原实现，app 保留薄调用；旧/new 行为比较只在测试运行，不在生产双执行。回退：撤回该调用和对应模块变动，存储结构未变。

### R2：审核编辑会话与图片操作

R2a 提取编辑源到字段的变换，R2b 整理保存及选题会话，R2c 图片确认/绑定/删除/裁剪的页面端口，R2d 复核一键确认入库与批量确认。每个子步骤限定一种职责，不连带修改识别。

候选文件：app 对应区域、ReviewDraftState/ReviewController 及明确页面会话模块；必要的现有持久化命令接线、图片命令 owner、相关 tests。ReviewWorkflowService 与 FormalAdmissionPolicy 作为既有规则边界，除非单独证实职责迁移需要，否则不改变其业务判断。

输入必须包括 batchId/draftId/expectedDraftVersion、编辑源/字段、必要图片证据和操作类型；浏览器端口处理 textarea/Canvas/Blob；领域层构建现有命令；存储成功后才更新“已保存原值”。保存失败不清缓冲、不重试覆盖；并发版本冲突不自动吞掉。

验收至少包括：选项解析成功与失败、图片 token 位置、PDF 候选编辑导致的确认失效、保存失败后再次明确保存、切题前未保存、放弃修改、切批次后的选择集合、已提交题不可误编辑、一键动作失败、批量部分失败。保留当前用户动作含义；发现缺陷先形成独立修复任务，不能混进无行为变化提取。

裁剪验收覆盖缩放坐标、页号/来源绑定、图片字节、取消及存储失败；真实原页不进入生产写入验证。完成后编辑原值与缓冲只有一份，确认/提交仍经过现有 workflow；禁止新页面模块直接 put 正式题。

### R3：导入装配及旧执行链退出

R3a 先列生产入口、重跑入口、历史批次身份、诊断/测试调用和全局暴露；R3b 每次退出一条已确认退役的执行链；R3c 把仍有效的装配收敛为明确端口；R3d 清相关缓存与失效工具引用。清理与装配提取分别验收，DOCX 和 PDF 迁移不在同一步混做。

必须分别回答：当前新批次用什么生产者；旧批次能否继续显示/审核；用户点击旧任务“重新识别”会发生什么。退役执行器后，历史身份不能被默默改成新身份。若重跑需要新任务，界面给明确可选择动作，不后台换路线、不恢复旧执行链、不新增第三条兜底路线。

## 19. 统一验证矩阵与证据管理

### 19.1 四层证据互相补充，不能互相冒名

| 层次 | 目的 | 明确限制 |
|---|---|---|
| 纯函数/合同 | 输出、输入不变性、反例、错误语义 | 不证明真实接线 |
| 合成普通 UI/隔离库 | 用户操作、状态、持久化、刷新与资源 | 不证明真实卷数学正确 |
| 真实材料＋历史外部回放 | 字节身份、完整字段/原页对照、本地 DOCX 链 | 回放不证明当前外部服务可用，不冒充在线重识别 |
| 独立内容/视觉复核 | 题目、答案、解析、图表与整卷排版 | 代理观察不冒充人工金标准；空标签继续为空 |

### 19.2 每步最低检查

1. 有必要的当前行为保护和负例，不写仅复述实现的测试。纯重构按固定输入比较输出、错误和副作用；时间/随机 ID 通过已有端口固定，不能忽略来源/版本/警告字段来制造一致。
2. 运行本步相应测试，再运行 `npm.cmd run verify:safe`。涉及导入/审核时运行 `npm.cmd run verify:batch-safety`；对应 app/加载变化运行 `node scripts/verify-app-shell-architecture.js` 和 `node scripts/verify-runtime-modules.js`。无新变化、失败或疑点时不重复同一重型门禁。
3. 检查唯一实际生产入口，不只测新函数。新模块有加载与消费者；未接线模块不能计入拆分完成。
4. 干净候选分支用严格 allowed-diff；当前混合工作区用本轮前后哈希和 Git 状态差异证明增量。现有 verify-diff-scope 会列出全部历史脏文件，不能把白名单放宽成全仓来伪造本轮范围通过。
5. 保存第一次失败原日志。业务失败若在范围外立即停；若是明确 EPERM，保留证据，在权限条件改变后重试同一命令，不改测试并冒充修复。

### 19.3 高风险操作矩阵

| 操作 | 必测拒绝/失败 | 成功后的读回 |
|---|---|---|
| 导入 | 角色/来源冲突、序列异常、未配置、取消、重复运行 | 批次身份、草稿字段、图片来源、警告与状态 |
| 编辑保存 | 不规范选项、保存异常、版本冲突 | 编辑源、字段、图 token、确认失效和版本 |
| 确认/提交 | 未采纳/未确认、不可转换公式、重复请求、写入失败 | 候选/已确认/正式题状态各自正确，未提交邻题保持 |
| 图片 | 缺 Blob、错误归属、裁剪失败、原页混题图 | 图片二进制、字段 token、页/块来源 |
| 题库操作 | 无效选择、重复合并、撤销边界 | 正式题、外部库、关系与图片一致 |
| 打印 | 失效题 ID、公式拒绝、坏图、资源未就绪 | 题答顺序、三种模式、整份输出的图文分页 |
| 备份恢复 | 安全包写失败、归档验证失败、中途事务失败 | 隔离 11 表和 Blob 一致，不动生产库 |

### 19.4 架构门禁迁移

现有责任矩阵冻结九个处理器及调用白名单。初期优先保留这些薄处理器；确需变动时给出原/新调用图、行为证据、允许范围与精确 hash 变化。既不能机械冻结导致无法迁移，也不能上调预算/自动刷新 hash 来绕过边界。新增加的一键确认/批量确认处理器不能因不在旧九个中就免于审查。

运行清单与 architecture、docs/architecture 必须对照既有规则更新，避免只更新一份；不把手工编辑的登记当实际运行证明。

## 20. 回退、失败处理与变更边界

- **历史整理回退**：W2/W3 不动原目录；失败的候选保留日志即可退回原基线。W4 更新原分支/索引前保存预期状态，发现并发修改立即停。不能用恢复包覆盖已经新增的用户工作。
