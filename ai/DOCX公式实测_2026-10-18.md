# DOCX 公式链实测（2026-10-18）

## 结论先说

**双 Word 导入的公式不是 OCR，是直接读 MathType 的底层 MTEF 二进制。**
用本仓库自带的真实真题实测：**212 个公式，211 个成功渲染成 LaTeX（99.5%）**。

## 实测数据

测试材料（`local-test-materials/case01-docx-docx-stable/`，未做任何修改）：

| 文件 | 大小 | MathType 公式 | Word 自带公式 | 内嵌图片 |
|---|---|---|---|---|
| `01-question.docx` | 268 KB | 66 | 0 | 3 |
| `02-support-answer-solution.docx` | 323 KB | 146 | 0 | 3 |

两份文件的公式**全部**是 `ProgID="Equation.DSMT4"`（MathType 6/7 的 OLE 对象），
没有一个是 Word 自带的 `<m:oMath>`。

提取与渲染结果：

| 环节 | 试卷 66 个 | 答案 146 个 | 合计 |
|---|---|---|---|
| 从 OLE 容器抠出 MTEF | 66 | 146 | **212 / 212** |
| 本地 JS 译成 LaTeX | 65 | 146 | **211 / 212** |
| KaTeX 能正确渲染 | 65 | 146 | **211 / 212（99.5%）** |

分类码分布：`MTEF_RECONSTRUCTED_OK` 194 个、`MTEF_TEX_SOURCE_OK` 17 个、`MTEF_UNREADABLE` 1 个。

**注意：这 211 个全部是纯本地 JS 翻译，没有调用 MathType 的 DLL。**
本机虽然装了 MathType（`C:\Program Files (x86)\MathType\System\64\MT6.dll`），
但那只是保险层；去掉它，本地 JS 依然能覆盖 99.5%。

## 唯一失败的那一个

- 文件：`01-question.docx`
- 位置：第 37 个公式（共 66 个）
- 上下文文字：**「已知复数，」** 后面那个公式
- OLE 载体：`word/embeddings/oleObject37.bin`（3072 字节）
- MTEF 长度：216 字节，分类码 `MTEF_UNREADABLE`

换成正规说法：这一处是 MTEF 结构里出现了当前解析器不认识的记录类型。
修它需要把这段 216 字节的十六进制打出来逐字节对 MTEF 规范，
收益是 1/212，优先级低。**建议导入后手动补这一个。**

## 代码链路（已确认存在且被调用）

1. `qisi-batch-importer.js:943` 调 `window.Qisi.DocxFormulaSource.expand(documentXml, relationships, zip)`
2. `qisi-docx-formula-source.js:40-60` 扫 `<w:object>`，只处理 `ProgID` 以 `Equation` 开头的对象，
   用 `qisi-docx-ole-reader.js` 从 OLE 复合文档里抠 `Equation Native` 流；
   抠不到时退回从 WMF 预览图的 `AppsMFC` 注释里抠
3. 先试本地服务 `/api/convert/mathtype-mtef`（走 MathType DLL），失败不报错
4. 兜底用 `qisi-docx-mtef-reader.js`（524 行）纯 JS 重建 LaTeX
5. `normalizeLatex` 用 KaTeX 校验，编译不过的会被判为 unresolved

**关键：路径拼接是正确的。** `parseRelationships`（`qisi-batch-importer.js:27`）
会给关系目标补 `word/` 前缀，所以 `Target="embeddings/oleObject1.bin"`
能正确命中 `word/embeddings/oleObject1.bin`。
（自查时用脚本站错过一次前缀，导致误判为"212 个全部提取失败"。）

## 因此：这条链不需要"修"，需要"别再动它"

DOCX 公式是这套软件里质量最高的一环。真正会出问题的是另外两处：

1. **答案表**：`题号/答案` 汇总表在混入填空数值答案时整表作废 —— 已修（见同日修复说明）；
2. **解析切分**：解析正文里行首的 `2.` 被当成下一题 —— **未修**，需要原页信息才能分清。

## 复跑方式

```bash
NODE_OPTIONS= node -e "
const JSZip=require('jszip'),fs=require('fs');
const ole=require('./qisi-docx-ole-reader.js');
const reader=require('./qisi-docx-mtef-reader.js');
const katex=require('./vendor/katex/katex.min.js');
const parseRels=(x='')=>{const m=new Map();String(x).replace(/<Relationship\b([^>]+?)\/>/g,(_,a)=>{const id=a.match(/\bId=[\"']([^\"']+)[\"']/)?.[1]||'';const t=a.match(/\bTarget=[\"']([^\"']+)[\"']/)?.[1]||'';if(!id||!t)return '';m.set(id,{target:(t.startsWith('/')?t.replace(/^\/+/,''):'word/'+t.replace(/^(\.\.\/)+/,''))});return '';});return m;};
(async()=>{let total=0,ok=0;
for(const f of ['local-test-materials/case01-docx-docx-stable/01-question.docx','local-test-materials/case01-docx-docx-stable/02-support-answer-solution.docx']){
  const zip=await JSZip.loadAsync(fs.readFileSync(f));
  const xml=await zip.file('word/document.xml').async('string');
  const rels=parseRels(await zip.file('word/_rels/document.xml.rels').async('string'));
  for(const o of [...xml.matchAll(/<w:object\b[\s\S]*?<\/w:object>/g)]){
    const rid=(o[0].match(/<o:OLEObject\b[^>]*>/)?.[0]||'').match(/r:id=\"([^\"]+)\"/)?.[1];
    const e=zip.file(rels.get(rid)?.target||''); if(!e) continue;
    const mtef=ole.extractMtefFromOle(await e.async('uint8array')); if(!mtef.length) continue;
    const c=reader.classifyMtef(mtef); total++;
    if(c.status==='extracted'){ try{ katex.renderToString(c.latex,{throwOnError:true,strict:'ignore'}); ok++; }catch(e){} }
  }
}
console.log('公式',total,'能渲染',ok,(ok/total*100).toFixed(1)+'%');})();
"
```
