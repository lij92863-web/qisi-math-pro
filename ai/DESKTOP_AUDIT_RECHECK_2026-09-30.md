## 3. 算法约束、正确性、成本与实测

### 3.1 事务内单次查重

约束：不改变现有规范化 S(q)、题干加选项指纹 C(q)、存储格式、记录顺序或决策码；数据库返回普通只读记录，没有可信预建索引。忽略软删除。扫描时暂存首个非空 S 相等项作为 similar，但继续找 exact；首个 C 相等项立即优先返回，只有该 exact 的答案按原规则判冲突。

不变量：处理前 k 条且未命中 exact 时，暂存记录恰为前 k 条的首个 similar。第 k+1 条若是 exact，它必是首个 exact；否则只在尚无 similar 时更新。初态为空，逐步归纳得到与旧 filter/find/find 相同的选择及决策。答案冲突没有改成“任意 similar 的答案不同”。

令 N 为记录数，T 为实际访问题干/选项字符总量，Lc 为候选字符量，扫描 O(N+T+Lc)。常数个匹配引用不等于整体 O(1) 内存：规范化字符串有临时空间，toArray 本身仍持有 O(N) 记录，移除的是之后整批深拷贝。返回的不可变结果还有候选指纹长度成本。

无索引模型中，最坏必须检查 N 条；也可构造某个尚未检查字符改变会将 NONE 改成 EXACT 的输入族，因此字符量下界为 Omega(T)。线性数量级达此模型下界，但不能证明常数最小或全项目最优。旧 `|`、`__` 分隔符并非无碰撞编码，例如相同题干、选项 ['A|B','C'] 与 ['A','B|C'] 得同一指纹；可能误判 exact/答案冲突。现有测试明确保留兼容，此次不擅自换格式，后续需核对数据库、批量、合并、导出消费者并设计迁移。

历史固定种子 10,000 组新旧结果一致，是有限输入对照，不替代归纳证明。7 次测量、每次平均 10 次、取中位数的历史 CPU 样本：1000 题 6.141→2.999ms，10000 题 61.789→29.507ms。旧口径含扫描与额外深拷贝，未计 IDB I/O、Vue、网络和模型，不称整体识别加速倍数。

### 3.2 批量提交的全局成本与新测量

生产调用：ReviewWorkflowService.submitReviewedBatch 逐题循环 → BatchFormalSubmit.submit → StorageRepository.confirmDraftToQuestion。每题在事务内 questions.toArray，做请求 ID 检查与查重，再按 batchId 读取草稿重计 submittedCount；工作流还会重新载入批次并 find 当前草稿。

M 条新题、初始 N 条正式记录，每次成功新增一条时仅正式库读行数就是 MN+M(M-1)/2；每题还处理至多 D 条同批草稿。因此固定长度记录模型上界包含 O(MN+M²+MD)，D≈M 时为 O(MN+M²)，并有 M 个提交事务。字符/记录大小不固定时须另计逐轮序列化、规范化与复制字符量。事务原子性与并发安全不能用跨事务缓存来换取漂亮复杂度。

本次在实际桌面加载模块、新浏览器上下文及独立原生 IndexedDB 夹具中，20 次调用生产 Formal Admission+正式仓库事务。每个规模 3 个样本、交错顺序，计时不含种库；使用事务内 Table 计时探针及只读策略包裹，保留原 Dexie Promise。没有 fake database 或业务 stub，没有写用户题库。

### 3.3 备份一致性、恢复与提交通知

备份在覆盖当前存在备份表的单个只读事务中读取全部记录；当前 schema 为 11 表。ZIP 编码、Blob I/O 在快照事务之外。恢复先将当前安全快照写入用户选择目录并成功 close，再在覆盖同一 11 表的 rw 事务内重新读取当前内容、精确比较、匹配后才 clear/bulkPut。同 store 写事务串行，不能在“比较成功与覆盖之间”插入另一个写者。恢复失败事务回滚；界面 inert，成功刷新丢弃旧缓存。

Blob 同长度、同 MIME 不代表同字节。SnapshotPolicy 比较元数据、类型及内容；每轮两个 1MiB Blob 块逐字节比较，Dexie.waitFor 保持事务。设元数据节点/键/字节量为 E、二进制字节 B，精确比较 O(E+B)；无可信摘要且需精确一致时有 Omega(B) 读取下界。两个块的临时二进制空间最多约 2MiB，但节点栈、Blob 引用、两份快照、ZIP 编码/解码及恢复数据另外占内存，不能称整个恢复只用 2MiB。

完整备份本身至少读/序列化所有被备份内容，压缩及校验还有真实成本；路径/大小/压缩比先检、full-backup CRC 后检。ZIP 格式和 CRC 一致不证明作者身份。旧备份缺表时 UI 显示，覆盖恢复会清空未包含表，不是无损合并。

工作区只有一个计时任务与一个 in-flight 备份；压缩前捕获变化代数，成功只将该代数标为已保存，过程中发生的新写入仍 pending。失败暂停自动备份；文件唯一名及同源 Web Locks 串行检查/创建，旧档不主动覆盖。外部程序恰好抢同名文件的 filesystem TOCTOU 不是现有证明范围，不为没有实际反例的极窄情形堆新分支。

自动备份只在用户选择目录后、本次软件打开期间生效，重开需重选；无后台服务、永久授权或自动删除历史档。逐行 creating/updating/deleting hooks、WeakSet 和额外 BroadcastChannel 已删除，复用 Dexie 3.2.4 原生 transaction-complete storagemutated（abort 不发）与其跨窗口广播；handler 检查 K 个 store/index 路径，O(K)，schema 固定时该检查与写 R 行无关。压缩/全库快照的成本未消失。

当前桌面完整套件实际通过多行一事务通知一次、回滚不通知、另一窗口同库提交通知、dispose 后停止，以及同尺寸 Blob 变化拒绝恢复的浏览器反例。此前三独立库、5000 行 bulkPut 的 6 个交错样本原始数据保留。**按通常偶数样本中位数（中间两值平均）重算**：无监听 178.95ms、旧 hooks 230.15ms、新事件 165.00ms。交接的 180.2/238.6/165.1ms 是上中位样本，非通常定义的中位数。波动明显；新事件样本小于无监听样本不能证明监听比无监听更快，亦无任意硬件保证。

### 3.4 其余算法与证明范围

OCR 支持解析保留原文/页/行区间，依靠表格拓扑、枚举和数学环境中的显式锚点；顺序异常不排序修补，受序列门禁及 field-level controlled write 限定 full/可靠 prefix/fail-closed。能安全分段并不证明 OCR 的数学表达式正确。

跨页规划只补充物理相邻、有题号与区域覆盖证据的连续原图；不会靠语义挂答案。索引避免逐次找目标，图像合成成本随处理像素数增长。令牌桶请求获取/释放 O(1)，并发由租约约束。这些限定结构/安全保证不涵盖任意扫描图像、任意模型输出，也没有全局最优证明。
