# 第一、二档问题的根因归类与通用解法（2026-10-18）

> 一句话：这 8 个问题不是 8 个 bug，是 **4 个坏习惯**。逐条打补丁只会越补越乱，
> 所以这份文档按「根因 → 通用机制 → 落地」组织，一个机制解决一类问题。

## 一、8 条问题归成 4 类

| # | 问题 | 归类 |
|---|---|---|
| 1 | 备份默认关闭，且从不提醒 | **A 保障机制没有出口** |
| 2 | 备份能创建、恢复时被拒（两把尺子） | **A** |
| 3 | 录题报「保存失败」但已入库 | **B 异步边界破坏原子性** |

| 7 | `参考答案：`/`【参考答案】` 标题认不到 | **D** |

## 二、A 类：保障机制必须"有出口、同尺子"

**坏习惯**：安全机制做了，但没接到用户能看见的地方；而且生成方给自己开后门。

具体表现：
- `hasRecentFullBackup` 写好了但没有任何界面调用 → 老师永远不知道自己在裸奔；
- `inspectBackup(blob, generatedHere)` 对自己刚生成的文件把上限设成 `Infinity`。

**通用机制（两条，不可拆）**：

1. **单一不变量**：一条约束只在一个地方定义。
   创建、校验、恢复必须共用同一个 `PROFILES['full-backup']`，禁止传入"宽松模式"参数。
   判断标准是一句话：**能创建 ⟺ 能恢复**。
2. **保障必须有出口**：任何"保护性检查"都必须有一个用户可见的状态位。
   做了检查但没人看得到，等于没做。

**落地状态**：
- ✅ 删掉 `generatedHere` 例外（`qisi-backup.js`），创建与恢复共用一套上限；
- ✅ 压缩比超限时**降级为不压缩重新打包**（备份要的是能恢复，不是省空间），
  而不是放宽安全限制；
- ✅ 失败码改成查表翻译（原来是三元链，加一个码加一个分支），并补上
  `ARCHIVE_TOTAL_SIZE_LIMIT` 等的中文说明 —— 原来一律显示"请检查文件夹权限及磁盘空间"，
  真实原因是"备份太大恢复不了"；
- ⏳ 「多久没备份」的界面提示由 `fix-backup-remind` 负责。

**为什么这不是打补丁**：改完之后，这一类问题不会再以"另一种形式"回来 ——
新增任何备份参数都只有一处定义，新增任何错误码都只加一行表项。

## 三、B 类：事务内禁止跨原生 await

**坏习惯**：用一个 `async` 函数包装数据库操作，再在事务回调里 `await` 它。

```js
const run = async (operation, work) => { return await work(); };   // ← 问题的源头
```

`async` 插入原生 Promise 微任务边界 → Dexie 事务 zone 丢失 → 事务在第二次操作前提交
→ 第二次操作抛错，**但第一次已经写进库了**。用户看到"保存失败"，其实已经存了。

**通用机制**：
**事务作用域内的所有操作必须返回同一种 Promise 实现**，不得经过原生 async 包装。
判断标准：事务回调里 `await` 的每个东西，必须能证明它属于同一个事务 zone。

**为什么不能"失败就重试"**：重试会写出第二份数据。这不是可用性问题，是数据正确性问题。

**落地状态**：
- ⏳ 由 `fix-tx-boundary` 负责：先用 `fake-indexeddb` 复现，再修，再验证并发行为不退化。
- ⚠️ 已知陷阱：直接改 `run` 的返回类型曾让 `pdf-qwen-simple-pipeline` 的页面并发
  退化成串行（415ms）。必须连带验证并发路径。

## 四、C 类：歧义必须"升级"，不能"消化"

**坏习惯**：信息不足时，代码替用户做选择，而且选完不留任何痕迹。

- 「保留更长的那段」——用长度当可信度；
- 「选质量分最高的一条，其余 merge 掉」——用分数当真相。

**为什么这是最危险的一类**：数学题里答案错一个字母就是错题。**猜对的收益远小于猜错的代价。**

**通用机制**：
1. **歧义对象化**：任何"多个候选、无法判定"的情况，产出一个结构化冲突对象
   `{ code, question, field, candidates[], message }`，**永不择一**；
2. **冲突必须可被消费**：发给评审页 / 草稿问题列表 / 批次警告。
   没有消费方的冲突等于静默 —— 这正是上一轮"清空 + 标记"失败的原因；
3. **只有完全一致才自动合并**：其余一律保留双方并标冲突。

**落地状态**：
- ⏳ 由 `fix-parser-ambiguity` 负责；
- 🚫 已废弃的两条错解法（写进文档防止再犯）：
  - 清空字段 → 静默丢数据；
  - 抛错拒整份 → 正常文件被拒导（样例：`1.【答案】A / 【解析】… / 2. 分两种情况讨论 / … / 2.【答案】B`）。

## 五、D 类：切分要"分层取锚"，不要"单一文本特征"

**坏习惯**：判断"这是不是新的一道题"时，只看一个特征 —— 行首有没有数字加分隔符。

后果成对出现：
- 该认的认不出（Word 自动编号的题号根本不在文字里）；
- 不该认的乱认（解析正文里手打的「2. 当 x>0」看起来和题号一模一样）。

**通用机制：锚点分层，越靠前的越可信。**

| 层 | 锚点 | 可信度 | 说明 |
|---|---|---|---|
| 1 | `<w:numPr>` 自动编号 | 最高 | 编号是文档结构属性，解析正文的手打分步不带它 |
| 2 | 已解析出的答案题号集合 | 高 | 答案说有几题，解析就该有几块 |
| 3 | 文本标记（行首数字+分隔符） | 低 | 只能兜底，且要配合"同编号第二次出现降权" |

配套规则：
- **按区域展开**：自动编号只在答案区之前展开，答案区里的分步列表保持原样；
- **同号第二次出现视为正文编号**：真第 2 题只会有一个起点；
- **标题识别用模式而非精确串**：允许书名号前缀、`【】`/`[]`、冒号、`及/与解析`。

**落地状态**：
- ✅ 新增 `qisi-docx-numbering.js`：按 `numFmt` + `lvlText` 生成标签
  （decimal / upperLetter / lowerLetter / roman / `(1)` / 全角 / 中文），
  不再只认 `upperLetter`；支持 `beforeIndex` 按区域展开；10 项测试；
- ✅ 接入 `qisi-batch-importer.js`，并删掉旧的 `expandWordLetterNumbering`（避免两套并存）；
- ✅ 答案标题统一为 `SUPPORT_HEADING_PATTERN`，14 种写法实测全部符合预期
  （`参考答案：`/`【参考答案】`/`答案详解` 现在认得，`【答案】B`/`答案：A` 不会被误认）；
- ⏳ 文本标记层的对齐与降权由 `fix-parser-ambiguity` 负责。

**真实材料验证**：`local-test-materials/case01-docx-docx-stable/` 两份真实卷**没有
`numbering.xml`**，题号是手打的，所以本次自动编号改动对它们**零影响**（安全扩展）。

## 六、执行纪律（防止再次改崩）

这次派了 3 个并行代理，按「改哪些文件会互相踩」分组，而不是按「问题条数」分组：

| 组 | 问题 | 独占文件 |
|---|---|---|
| `fix-backup-remind` | A-1 备份提醒 | `qisi-backup-workspace.js`、`main.html` |
| `fix-tx-boundary` | B-3 事务边界 | `qisi-storage-repository.js` |
| `fix-parser-ambiguity` | C-4 / C-8 / D-5 | `qisi-support-text-parser.js`、`qisi-production-import-output-port.js` |

三条铁律（上一轮踩过）：
1. **不允许为了变绿改测试期望**，除非该断言本身锁死了错误行为，且必须写明理由；
2. **修 bug 不得以"正常文件被拒导"为代价** —— 这条优先级高于修好；
3. **不许一条问题改两版都回滚就宣布"已修"**，做不到要说做不到。
