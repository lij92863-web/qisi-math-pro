# PDF 回执协议与恢复修复

用户明确要求继续从根因修复整卷测试中的所有缺陷，禁止深圳卷特例、默认值掩盖、重复框架及 app.js 业务膨胀。保留当前已授权脏工作区及全部历史证据，不提交或推送。

## 根因与范围

1. 视觉 JSON Object 只保证 JSON 格式；当前官方文档明确多模态 json_schema 会降级。因此仍用已支持的视觉模式，不把严格输出参数当解决方案。
2. 定位执行数据（来源、页码、状态、区域类型、坐标）与诊断报告不是同一类约束。输入侧允许省略诊断列表，但必须把“未报告”保留为独立待核查证据，绝不解释为无问题。null 框、unreadable 状态仍要求明确原因；错误类型及核心字段缺失继续拒绝。输出提示仍要求完整报告，原响应逐字保留。
3. 使用已有 attempts 回执保存与内容身份，实现固定 R/L 序列的已收结果复用。只在明确开始的新运行中使用来源、请求哈希、响应哈希、模型、终止状态和现行页合同均有效的回执；保留物理账本，缓存命中不新增请求/费用。未知、取消及同版本失败封锁仍生效。版本修复后的新运行可以复用匹配的有效步骤，所有未解决问题继续携带，不自动修订或入库。

Allowed files: qisi-pdf-page-evidence.js, qisi-pdf-external-provider.js, qisi-pdf-external-producer.js, tests/pdf-page-evidence.test.js, tests/pdf-qwen-simple-pipeline.test.js, tests/e2e/pdf-external-chain.test.js, 相关 ai 文档及 local-run-artifacts 下离线证据/执行器。

Forbidden: app.js、DOCX 解析、DB schema、生产数据库、源材料、旧回执及账本、凭据/环境配置、依赖、无关重构。不得添加重试调度器、字段语义猜测或以空默认值放行异常。
