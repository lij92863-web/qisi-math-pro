## 3. 不变的架构与明确暂缓项

```text
PDF → 本地渲染 → 配置窗口 → 单模型直接结构化输出
    → exact key 关联/保守去重/冲突保留
    → 原 PDF 裁图 → 验证 → 当前版本人工确认 → 原有事务入库
```

原题号是字符串，关联 key 为“导入身份 + 原题号”。不同内容不自动选赢家，不按顺序平移，不按数学相似度、长度、公式密度匹配或合并。AI 结果不再穿过旧 parser/选项重拆/题型猜测/Markdown 支持 parser/评分 merger；DOCX 的 XML/OMML/MathType 链保持独立。

第一阶段仍使用 qwen3-vl-plus，不引入 Flash/Plus 路由、OCR 第二提案、模型共识、section registry、scope mapping、全文 bbox、长解析 fragment、自动评分或版本树 UI。不为每个流程框新增一个 owner。

下一轮每段业务逻辑须解释：“它在验证模型，还是替模型理解试卷？”不能回答清楚就不进入生产。发现了真实异常，不等于必须增加一个异常专用算法。

**特别核对 finishReason 和实际输出量。** 现有不少响应正常 stop，输出明显低于本地 16384 上限，仍漏步骤/错归属。不能没证据就认定全部漏文是 Token 截断，也不能盲目把上限调大解决所有问题。

固定窗口提供重叠，不保证完整单元总被正确理解；源码里有跨页处理原则，不等于模型执行了原则。当前 strict conflict 又会把“半段 vs 整段”保留为冲突，这是正确的保守接收行为，不应拿放宽比较作为识别率优化。

## 8. C：最小候选方案与选择方法

先用已保存响应/金标评价，不重复付费。真正需要新模型输出时再做限额实验。

| 候选 | 变化 | 优点假设 | 主要风险 | 是否默认实现 |
| --- | --- | --- | --- | --- |
| 0 当前配置 | 5 页、重叠 2、当前 prompt | 已有基线和安全闭环 | 混合任务多、长解析/边界遗漏、冲突高 | 保留基线 |
| 1 更聚焦的指令 | 同页/同分辨率/同模型/同 Schema，简化重复指令；明确全文与归属要求 | 减少同时分类、改写和输出干扰 | 强 prompt 不保证模型忠实；改善可能不稳定 | 首先小样本试验 |
| 2 一组窗口参数对照 | 只选一种替代，如 4+1 或 6+2；其他固定 | 检验负载与相邻上下文是否关键 | 小窗口缺上下文，大窗口输出更多且易漏 | 在 B 的证据指向窗口时试验，不同时扫全部参数 |
| 3 明确角色的整单元重读 | 指定原题号与原源页，题目或答案解析集中转写为完整对象 | 异常修正由模型重新读完整单元，不本地拼接 | 增加调用；也会改写/漏文；页不足仍失败 | 先人工触发的局部实验，不做全卷双遍默认主链 |

推荐顺序：确认输入可靠 → 聚焦指令或窗口的一个因素 → 如果全局配置仍不能可靠处理少量异常，再试人工触发的整单元重读。当前数据不足以宣称某一配置最优。不要一次同时改模型、分辨率、窗口、prompt 和 Schema，最后无法归因。

如果指令对照胜出，就只部署胜出指令；如果窗口胜出，就只部署该配置。若都不能减少严重错误，不加本地语义补丁，也不无限迭代 prompt；如实列能力边界和证据，另行讨论模型变更。更强/其他模型不属于此规划的默认实施范围。

## 9. D：必要时的整题重读设计

这是实际跨页/归属问题支撑的可选小扩展，不是一套自动升级架构。只有 C 证据表明需要，才登记精确实施范围。

初版流程：教师在该题审核页点击“按原页重新识别” → 明确原题号与需要的源页/字段 → 同一模型读取包含前后文的完整源页 → 返回现有 Schema 中该题完整 question 或 answer/solution 对象 → 严格验证 → 作为新候选展示 → 教师选择/修改 → 重新确认。

初次创建任务仍只选择题目/答案/题目+答案角色；不增加必须手选的识别模式。重读只出现在处理异常时，不让所有教师先标每页类型/划题边界。

约束：

- 页来自同一明确源文件、原页号合法；目标题号明确，不能通过关键词找“最像”的题。
- 输出完整字段单元，禁止 prefix/suffix、continue、fragment 拼接协议。
- 对该窗口不能见全内容的结果仍 partial，不为了拿到 complete 扩大到无限页。
- 结果是待审候选。最新模型、长内容、状态 complete 都不能自动覆盖旧候选。
- 旧原响应、旧候选保留，新选择使旧确认失效。仅复用现有简单 candidate 结构，不造 revision tree。
- 请求针对目标题，不丢弃正常草稿、不付费重跑全卷。
- 不把已出现的错误题号硬编码为特例；触发入口对任何明确题号/页均可用。
- 不能自动保证发现所有静默漏文；模型 complete 仍要核对，程序没有再写一次语义理解器。

如果现有默认路由不接受“题目+两个支持文件”，继续明确拒绝。多 PDF 作用域/路由扩展不捆绑本轮。

## 10. 图像策略：先确认坐标，再改善模型定位

区分两类缺图：

1. 原 bbox 已包含点名而本地裁掉：检查原页尺寸、缩放/旋转、坐标换算，是确定性裁取错误，只修 renderer。
2. 原 bbox 本来就不包含点名：这是模型定位错误，不以统一加 5% 边距当通用修复。

先在现有原图/原 bbox 回放，核实第二类在当前样本的比例。模型定位要求强调完整点名/轴端；可在局部重读中让模型重新返回该图 bbox，裁图仍来自原 PDF。原图不好读时可提供更清晰原页面/局部图，坐标必须保留明确可逆变换；不要默认增加视觉 grounding 服务。

图无墨迹、越界、非法归属、资产缺字节仍按图失败。对多个合法但不同 bbox，不做质量评分自动挑一个；教师可选/手工重裁。手工 crop 是异常处理工具，不能靠重裁所有图宣布模型归属正确。

## 11. 协议与本地验证保持轻量

继续现有 questions / answers / solutions 三数组；原题号、type、正文、options、figures、source_pages、status、warnings。不默认新增 confidence、所有文字 bbox、section/scope/anchor 或 fragment。

本地继续检查 JSON/字段形状、题号 key、页码范围、选项标签、答案标签与题型矛盾、图 bbox/来源/像素、重复冲突、数学可渲染性、确认版本、事务回读。

“单选 + ABD”可以阻断，但不能自动改成多选；“公式可渲染”不证明式子抄对；“相邻页都处理了”不证明两页之间没有漏句；“解答题有一段解析”不证明完整证明；“像素不空”不证明图归属正确。不要用增加规则数量包装这些能力缺口。

若模型给出正常但错误结果，本轮通过金标/源页验收发现。生产默认仍要求教师核对。不能宣称 deterministic validation 能证明一切模型文本语义真实。

## 12. 正确性证明能证明什么

实施任何新调度/缓存/投影要说明前提、结论、反例和复杂度。

- exact key 可证明漏一题不会引发本地按位置整体平移；不能证明模型为错误解析写了正确题号。
- 固定滑窗 size>overlap≥0，步长>0，可证明请求页覆盖；不能证明任意跨度的整题必落在一窗内。
- 整单元重读不本地拼接，可证明没有程序猜补半段正文；不能证明重读模型忠实。
- 冲突保留/人工选择可以证明不自动评分择优；不把教师选错当成程序可证明正确。
- 原像素裁图可证明没有重绘；图属于哪题和是否漏标签需验收。
- 新确认依赖新版本、资产实际回读与事务一致性可由反例/闭环证明，不刷新保护 hash 掩盖行为变化。

多模态模型的全局最优识别无法从这些证明推出。成本、正确率、速度同时优化也需要真实对照数据；只能报告在试过的配置与样本上哪种更好，不能包装为无条件全局最优。

### 19.2 首个已复现问题：坏 JSON 被当成成功缓存

**现象：** 某窗口的模型调用正常 `stop`，但正文不是合法 JSON。第一次导入保留其他成功题目并记录窗口失败；保存任务后重新识别，该失败窗口反复使用旧坏响应，完全不调用新识别端口，即使端口现在能返回正确内容也无法恢复。

**代码依据：** `qisi-pdf-multimodal-producer.js` 在 `parseResponse` 之前把包含 text/finishReason 的响应放入 evidence；查缓存只检查 sourceId、cacheKey、非空 text 和 `finishReason === 'stop'`。没有区分“原响应已留证”和“该响应已通过协议校验”。`cached` 在重试循环外固定，坏缓存的两次尝试仍是同一个响应。

**离线反例：** 两个单页窗口，第一页成功、第二页首次返回非法 JSON。把第一次输出 evidence 保存到 source 后再次运行；第二次端口预设可以返回合法 JSON，但实际调用次数为 0，草稿仍只有第 1 题，错误仍是 `PDF_V1_JSON_INVALID`。此反例使用真实 producer/contract/identity，仅替换渲染和模型端口，没有网络调用。

证据和复现脚本在项目外：

- `E:/备份/题库系统/local-run-artifacts/pdf-v1-next-round-plan/reproduce-invalid-window-cache.cjs`
- `E:/备份/题库系统/local-run-artifacts/pdf-v1-next-round-plan/invalid-window-cache-reproduction.log`

**处理要求：** 原始坏响应继续完整留证，但不能作为可用成功缓存。最小修复应在现有 producer 内保证只有通过当前 JSON/Schema/窗口页及角色验证的响应可复用；旧缓存也必须经过同一验证。无效缓存走该窗口有上限的新请求，不再次把同一坏缓存当重试；成功窗口继续复用，不丢弃已有成功草稿。不能仅删坏证据、增加无限重试或整体重新消费一份试卷。

实现时选择一次验证的最小控制流，避免新建另一套缓存框架。在现有 V1 测试中保留一个业务回归：成功窗口零重复请求，失败窗口收到新请求并恢复，两题最终存在，原坏响应留证。相同边界的 schema 错误、截断/空响应属于参数化核查，不为每种错误再写一套大状态机。本问题当前状态为 **已复现、未修复**；修复后须更新执行报告并用同一反例复验。

| 边界 | 核查的业务事实 | 最小验收证据 |

| UI/路由/来源 | 当前任务只进入 V1；两个任务、两个同号来源不会串卷；未知 producer 不回落旧链 | 正常 UI 日志和实际调用图；同号不同任务的隔离反例 |

### 19.4 旧链与新链：不能只看文件是否还在

对 main 脚本、全局 Qisi 引用、工厂注入、各 producer route、output port、review normalization、历史草稿复认和错误 fallback 同时做静态扫描与实际运行核对。至少证明正常 PDF、API 失败和复认三条路径没有调用旧的 OCR→Markdown→题号/选项拆分→语义评分→挂接闭包。API 失败仍由新链局部恢复或交人工，不以“兼容”名义暗用旧 producer。

分类必须写实际消费者：

1. 旧 PDF 执行逻辑：无合法当前用途的入口、分支和专用 helper 删除。
2. 当前 DOCX/通用基础设施：保留，验证 V1 输入不能误进入其语义分支。例如 sequence gate 名称带 PDF，却仍是 DOCX 的真实依赖，不能按名字删除。
3. 历史数据读取：保留最小展示/身份验证，不能在读取或复认时隐式恢复旧识别。
4. 测试/工具残留：迁移仍有效业务断言，退役纯旧实现消费者；受保护文件按明确例外处理。保留引用清单，不能把 dormant 文件描述成产品仍在走双链。

静态零引用不是动态不可达证明；浏览器没有加载某文件也不足以证明共享 output/review 分支没有改写新字段。验收要同时提供静态依赖和三条实际路径记录。不要为了显示“删干净”破坏 DOCX、正式题历史读取或现有事务。

## 20. 必做：性能、准确性与证明，避免以复杂度换假优化

### 20.1 先定位消耗，再决定是否改算法

分别测量渲染、窗口组装/哈希、真实模型时间、JSON/分组校验、裁图、草稿写入、审核读取、事务入库/重载；记录请求数、输入/输出 Token、费用、峰值内存、图片/证据实际存储字节与墙钟时间。API 等待与本地运算分开。最新报告的约 4–8 秒离线回放时间不含模型延迟，不能拿它当真实识别速度。

使用现有两卷，冷导入和同版本重新识别各测；本地部分至少三次重复，说明机器、缓存状态、运行配置和中位数/波动范围。10/20/30/50 页的本地负载可用离线固定证据测资源趋势，注明是合成负载，不据此宣称模型准确性或真实成本。收费实测仍受剩余 43 次限制，不为性能重复烧完整卷。

当前代码值得量测的具体点是：producer 在渲染完来源全部页面后保留页图；哈希输入包含图 data URL；每题保存 sourcePageImages/responses 可能带重复大数据；按题/字段裁图是否反复打开和渲染同页；`find/filter` 是否导致候选增多时反复扫描。它们目前是**瓶颈候选，不是已证明性能 bug**。确认后优先现有生命周期内复用、减少重复计算/复制，不能直接新增持久化缓存、并行请求池、分布式任务或复杂引用图。也不能只统计内存对象共享而忽略 IndexedDB 序列化后重复写入。

性能改动必须回答：实际慢在哪里？该改动减少哪一项工作？取消/资源释放/确认语义是否保持？峰值内存是否恶化？若耗时主要来自模型，而本地检查只占很小比例，不为了毫秒删除安全验证。若缓存命中仍重渲染，先量清渲染与请求分别占比，不未经依据建设第二套缓存。

### 20.2 准确性必须衡量最终题目，也必须衡量程序忠实性

按第 14 节对 38 题建立逐题对照：题号/题型、完整题干、每个选项、关键公式、每张图及归属、答案、完整解析和跨页尾文。原卷、原模型结果、程序接收结果、人工修订结果四份分开。若原响应正确而草稿错误，修程序；原响应已经错误，查输入/窗口/指令；源页真有歧义，记人工边界。金标也是人工产物，河北 8 的勘误证明它同样需要源证据复核。

新增一个跨层不变量：教师未明确修改时，选定候选的业务字段到草稿和正式重载不发生语义改写。JSON 解码、字段容器映射和原像素图片 token 挂入允许发生，但每项必须可解释、可对照；不能以显示清理为名改变公式、选项或答案。去重只允许既有保守排版处理，不能对数学表达做等价化、化简或相似度判断。

报告机器初始字段错误率、整题全部正确率、错挂次数、人工复核率和人工修订量。严重错挂与漏项分别统计；“被拦截”是安全行为，不能算正确识别；“需人工审核”也不能掩盖整卷大部分字段错误。深圳/河北是回归与反例集，不是所有版式的随机代表，结论限定这两卷。深圳 5 字形仍待核对；深圳 13 孤立 0 属源文，不能误统计为 AI 幻觉。

### 20.3 算法证明的边界和优化接受条件

对真正新写或改变的确定性算法写简短的前提、正确性结论、不变量、终止性、时间/空间复杂度和反例。exact key 可证明不因缺号平移，但不能证明模型抄对了题号；协议验证可证明不接受非法结构，但不能证明合法文本忠实；图裁取可证明像素来自原 PDF，但不能证明模型框出了完整图。

“全局最优”只有定义了有限可行域、目标和约束，且能排除全部更优解时才成立。例如以明确题号做映射可说明查询复杂度，但不能由此推出整条 PDF 识别在准确率/成本/速度上全局最优。多模态输出和未知版式没有这种可用保证。本轮可证明程序安全/复杂度，可以实测候选方案改进，不能承诺有限样本的最优就是所有试卷最优。

接受优化必须同时满足：原始证据与确认边界保持、相关反例修复、两卷已正确字段无新增退化、DOCX 稳定链通过，并有对应耗时/资源/成本数据支持。用户新增的硬要求见第 21 节：任何作为优化提交的新算法/方案，至少一项速度、资源性能或费用有可核实的实质改善，且识别质量与处理效率不下降；成本专项必须证明完整费用下降。准确性/安全 bug 修复单列，必要修正若增加耗时应明示，不伪称性能优化。没有实测改善或证据不足就不部署额外复杂机制。

## 21. 必做：重新设计降低调用成本的方案，并证明收益

### 21.1 用户新增目标与强制准入条件

用户认为当前调用费用仍偏高，要求接手人重新思考输入、窗口、输出、复用与请求策略，设计能在**不降低识别质量与处理效率**的情况下降低费用的方案。不能以“目前每卷几毛钱可以接受”代替这项工作，也不能只写一份省钱技巧清单。应提交当前方案、多个可行候选、否决依据、推荐方案及其证据，再决定是否实施。

所有拟作为优化实施的新算法或新方案，必须过以下准入条件：

1. 原题目内容、exact key、原像素、冲突保留、确认和事务安全约束保持；不能通过漏解析、降图片完整度、少返回题目、降低校验或增加静默错挂来省钱。
2. 识别质量不低于修复后的基线，处理效率不低于基线。先定义比较口径和测量误差，再实验，不能看到退化后临时放宽标准。
3. 至少证明一项实质收益：端到端更快、相同业务负载的资源消耗更低，或者完整单份费用更低。仅“代码更短”“调用数少”“理论上应该快”不满足此条。
4. 本节成本专项的胜出方案还必须有**完整费用确实下降**的证据；只加速本地渲染、API 账单不变，可算性能优化，不能算已完成降费目标。
5. 不能把教师额外补录、人工检查大增或失败率上升排除在代价之外。机器初始质量、人工修订量、审核耗时都要保留。

比较基线应先修复已确认的安全/恢复 bug，避免拿“坏缓存永不恢复、因此永不再收费”这种错误行为作为便宜基线。安全修复首先以功能正确为准，不要求为了修 bug 同时创造费用收益，也不得将它混报为降费优化。

### 21.2 先建立真实成本账，而不是按调用次数猜费用

从已保存账本和响应提取每次请求的：源/窗口、模型与版本、prompt/config hash、输入与输出 usage、可用的缓存计费分类、终态、耗时、重试原因和账单。不要打印密钥或源材料到公共日志。旧响应 usage 可以离线核算，不为“重新算账”重复请求。

令每次实际计费请求的各类 Token 为 T[j,k]，对应官方价格为 P[j,k]（元/百万 Token），则：

```text
C_document = Σ_j Σ_k T[j,k] × P[j,k] / 1,000,000
             + 已确认的其他计费项
```

j 必须包括失败后的新请求、自动重试、局部复核和升级请求，而不是只包括最后成功的一次。k 使用实际服务返回和计费规则：如果视觉 Token 已包含在 input usage 内，不能再把图片估算 Token 重复加一次；若实际有独立计价类别才拆分。服务端缓存命中可能仍计费，不能当作本地零调用缓存。价格档位、上下文阈值和模型版本在实验前从官方文档重新核实并注明日期，不沿用旧价格来宣布新方案省钱。

缺失 usage 或账单的失败请求记为费用未知，给出已知小计及未知项，不把未知记 0。深圳历史约 ¥0.322270 只代表已记录的那一轮；河北目前没有完整可用单轮成本，不能拿不完整失败账单做公平比较。

分别给出：首次完整导入成本、同版本重复导入成本、单失败窗口恢复成本、正常单卷成本和包含失败/局部复核的观察期总成本。不用大量缓存热跑把首次成本“平均”得很低。另报每道机器完整正确题的成本；分母为源页核对后的正确整题数，不能用模型输出题数或人工修好后的题数充数。质量不相等的方案，不能只比较总价。

费用归因至少回答：视觉输入、prompt/辅助文本、输出全文、窗口重叠导致的重复输入/输出、失败重试分别占多少；无法从 usage 精确拆分的部分标估算。根据这份账再确定优化优先级。

### 21.3 当前窗口成本的可证明部分

当前默认 window_size=5、overlap=2。对 N≥1 页、窗口大小 W、0≤O<W，当前 `windows` 实现的窗口数及页面输入次数为：

```text
K(N,W,O) = 1 + ceil(max(0, N-W) / (W-O))
S(N,W,O) = N + O × (K-1)
```

证明：首窗最多覆盖 W 页；之后每次起点向后移 W-O，新覆盖至多 W-O 页，故还需 ceil(max(0,N-W)/(W-O)) 个窗口。后续相邻窗口在达到文件末尾前均重复 O 页；最后窗停止在末页，所以总页面出现次数等于全部 N 页加每个相邻边界的 O 次重复。仅适用于当前连续等步长、覆盖所有页的实现；改变调度后需重新推导，不能照搬。

| 原页数 | 当前窗口数 K | 页输入次数 S | 重复页输入次数 S-N |
| --- | --- | --- | --- |
| 10 | 3 | 14 | 4 |
| 20 | 6 | 30 | 10 |
| 30 | 10 | 48 | 18 |
| 50 | 16 | 80 | 30 |
| 深圳 21 | 7 | 33 | 12 |
| 河北 19 | 6 | 29 | 10 |

两卷 40 个原页当前输入共出现 62 次，22 次是窗口重叠；这指出了应研究的重复负载，**不能推出消除重叠即可省 22/62 的总账单，也不能推出质量保持**。prompt、输出、计费档位、失败重试和不同页面视觉 Token 会改变实际比例。跨页上下文是重叠的功能价值，不允许未经验证直接降到 0。

本次只做文档验证：实际调用当前 producer 的纯 `windows` 函数，对 N=1–100、W=1–10、每个合法 O 共 5500 组配置核对 K/S，均一致；没有调用模型。这是公式和当前实现一致的检查，不是识别率证明，也不是新方案胜出实验。

### 21.4 必须比较的候选，先研究再选择

以下是候选研究范围，不是全部都要实现，也不是预先指定赢家。优先考察只去掉无效重复工作、仍保持一条主链的方案。

| 候选方向 | 预期减少什么 | 必须提供的证明/实验 | 不准偷换的条件 |
| --- | --- | --- | --- |
| 有效窗口响应精确复用，失败仅重试本窗口 | 重复导入、断点恢复时的收费请求 | 复用键覆盖当前源/输入/指令/模型/协议所需变化；协议验证后才可用；正常窗口零外发、失败窗口可恢复的调用记录 | 坏响应仍留证但不命中成功缓存；不能复用旧确认；热跑收益不能冒充首次降费 |
| 缩短重复 prompt、输出紧凑 JSON | 文本输入和纯格式输出 Token | 逐项说明删掉的是重复说明/无业务信息格式；当前与候选配对实测全文质量、Token、费用和耗时 | 不删原解析步骤、来源页、图片归属或不确定警告；协议字段变更需最小兼容验证，不重造大 Schema |
| 比较一个有证据依据的窗口/重叠配置 | 重复页和重复全文、重复 prompt 的计费 | 先用 K/S 和历史 usage 估算；再测跨页题、长解析、冲突率、重试与总价 | 大窗口少请求不等于便宜；小重叠省输入不等于跨页安全；不默认整卷一次、不本地拼碎片 |
| 比较一个合理的统一识别分辨率/图像输入规格 | 可能降低视觉 Token、传输与渲染耗时 | 核实服务视觉计费/缩放规则，测实际 usage；重点核指数、根号、分数、图标注的退化 | JPEG 文件变小不保证收费 Token 变少；原 PDF 裁图仍保留高分辨率；不先建页型路由/多级图像策略 |
| 已选角色/明确范围下去除无效输入 | 重复发送与本任务无关的材料 | 使用教师明确选的角色/范围，或经证明没有可见业务内容的页面；留原页映射并核对覆盖 | 不根据不可靠文本层或一套本地题型规则推断“这一页没用”；没空白页就不造空白检测框架 |
| 必要时只重读有明确题号的完整单元 | 整卷重跑的费用和等待 | 比较一次完整重读的成本与原实际全卷重试成本，验证其余成功题不重跑、目标内容完整 | 不拆成长解析 fragment；不强制每卷二遍；不把增加人工定位的代价隐去 |
| 服务端提供的折扣/缓存/批处理能力 | 相同输入的实际单价或重复前缀费用 | 仅在官方确认当前 API/模型支持后研究，算实际命中率和费用；核对延时、可靠性和使用限制 | 不假设有该能力；排队变慢不满足效率要求；不另接未经授权服务 |
| 更低单价的单一模型，或异常升级 | 可能降低模型单价 | 先写准确性、实际可检测失败比例、二次调用与时延的成本模型；已有金标足够且权限覆盖后才测试 | 第一版仍保持当前单模型；本节允许研究，不默认实现多模型路由，不扩大真实调用权限 |

可以提出表外方案，但同样交证据和复杂度。PDF 文本层如作为辅助必须测其实际收益和错误影响；不把它升为纠正模型正文的第二语义主链，不另加付费 OCR。不能只因某字段 output Token 多就删长解析，因为这恰好是用户需要的业务内容。

推荐的研究顺序是：真实费用归因 → 可靠复用/局部失败恢复 → prompt/纯格式冗余 → 由证据选一个窗口或输入规格对照。只有这些不足且预计净收益足够，才进一步研究模型替换或服务能力。最终推荐可维持现状，但必须明确哪些候选被数据否决，不能无实验就说“已经最优”。

对“便宜模型 + 强模型复核”，若原强模型单次成本 C_s、便宜模型 C_c、实测升级率 p，则单次初步预期费用为 C_c+p×C_s；降费必要条件是 C_c+p×C_s<C_s，还须计入重试、上下文差异与额外等待。p 不能用模型自报 confidence 或只统计发现的错误估算：无法检测的静默错误同样影响质量，因此这个不等式本身远不足以批准路由。没有真实 gold/失败检测和预算证据，暂不实现。

### 21.5 严格证明与实测：每个方案必须交一张证据卡

每个候选先填写以下材料再写业务实现，最终保留原始数据：

```text
方案 / 当前基线版本与 hash：
解决的已测成本或性能问题：
唯一改变的变量、明确不变的边界：
输入假设、适用范围、反例与失败条件：
正确性不变量、终止性、时间/空间复杂度：
费用公式与待测参数，包含失败/复核/重试：
预先规定的质量、时延、资源、费用比较标准：
实验源/页/题、配对基线、模型/配置/价格日期：
原 usage/耗时/字段差异/人工改动记录：
收益数值及比例、波动/不确定性：
是否达标、没有证明的部分、最小实施/回退范围：
```

证明分两层，不能互相冒充：

- **确定性算法层：** 数学说明在前提下结果保持、请求/复制/扫描等工作量如何减少，包含最坏情况与额外内存。例如相同有效输入精确复用可证明没有新增模型请求；映射索引可分析从反复扫描到预期线性构建/查询的复杂度。但还需量测哈希、构建、持久化等常数成本，不能仅 O(n²)→O(n) 就宣布小卷更快。
- **模型/网络方案层：** 识别质量、真实延迟、Token 与失败率是经验量，必须同源、同字段 gold、固定版本配对实测。不能数学证明多模态模型对所有试卷同样正确，也不能从减少图片字节推断收费下降。样本不足或延迟受网络波动无法归因时，结论是“证据不足”，不是“已严格证明”。

局部实验保持单因素，先核预算再请求。保留 baseline 和 candidate 原结果；不挑最好一次对最差基线。能复用的同版本基线不重复付费；每个请求只改变已登记变量。模型随机性需要在预算允许范围内做配对重复，且同页多题不是多个独立模型实验，不能把 38 题直接充当 38 次独立样本。说明各指标的观测差和合理不确定范围，若无法区分噪声，就不以加速/省钱作为发布依据。

识别质量不下降的验收：在两卷和实际受影响的跨页/小字/图题上，没有新增错题号、错答案/解析归属、错图或原已正确关键公式变错；逐字段和整题质量至少保持，漏文/冲突/人工修订量不得被平均数掩盖。效率不下降同时看完整流程中位时间与尾部时间，不只看首个请求更快；CPU、峰值内存和存储必须受已有约束，不用翻倍资源换一个漂亮速度数字。

对成本专项，冻结适用范围后要求观察到单份总费用下降；差异若落在计费或估算不确定范围内不能算达标。同时报告绝对省多少钱、百分比、实现维护成本和回收条件，决定是否值得改。无需凭空规定所有方案都必须省 20%，但目标/测量阈值须实验前登记，不能事后挑一个极小差异宣布成功。

这种证明能支持“在明确假设/这些样本下改进”，不能支持陌生版式的无条件全局最优。若用户要求的零退化无法被现有数据充分支持，应保留当前可用配置、交完整否决报告，不能硬发一个未经证明的便宜版本。

### 21.6 预算、迁移与最终交付

本节是设计和验证要求，**当前不修改业务代码、不发收费请求**。真实调用仍限原两份深圳/河北文件、已有目的地与当前明确模型权限，账本仍 107/150、剩余 43。研究其他模型/服务的文档不等于获准向它们传材料；新真实调用权限不从“写入规划”推定。

使用既有单因素实验、旧响应 usage 和离线资源测量优先筛选，不为每个候选各跑一遍 40 页。第 13 节的预算是共享总额，本节没有额外 43 次；成本实验需要从原分配中挪用并保留最终全卷验收的足额请求/重试空间。若预算无法支撑质量非退化与降费证明，先完成方案/公式/估算及本地可证改进，明确付费证据缺口，不挤掉最终验收。

部署只选达到准入条件的最小改动，仍走 V1 单主链及现有审核/事务；不为了节省少量 Token 实现庞大的调度、版式规则或多模型共识系统。不复活旧 OCR/parser 以“免费”补模型漏文。改变 prompt、窗口或图像输入后缓存键和候选确认须相应处理，不能用旧缓存伪装成新方案识别结果。

总报告增加以下内容：

1. 当前成本分解和首次/复认/失败恢复的独立账；未知费用明确列出。
2. 至少比较当前方案与两个有依据的候选；可先用解析推导否决不可能更好的候选，不要求为凑数量付费。
3. 每个进入实验候选的证据卡、配对原结果、成本推导及准确性/效率非退化核对。
4. 推荐方案与舍弃方案、至少一项实际收益；成本专项另给费用下降证据。没有胜出就明确未完成降费目标，不写成“优化已完成”。
5. 对典型 10/20/30/50 页给出经实际 usage 校准的费用估算和不确定范围；对深圳/河北给出实测基线与候选费用、时间和质量。估算与实测分别标记。
6. 修复/优化后的最终门禁、完整题目验收、DOCX/历史数据/图片回读与退役状态；保持第 19–20 节全部约束。

交接要求：**先解释并证明为什么会更好，再用数据验证，最后才做最小替换。至少一项真实收益、识别质量与效率不下降；成本目标须真实降费。否则不实施该优化。**
