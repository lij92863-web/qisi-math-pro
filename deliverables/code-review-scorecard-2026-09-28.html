一句话结论

你的"业务脑子"是专业级的，但"工程脚手架"已经开始遮住你的眼睛。

不夸张地说，这个项目对"宁可没有答案、也不能挂错答案"的坚持，比很多商业软件都强——PDF 对齐的三态判定（完整／只给前缀／直接放弃）写得干净克制，还有成体系的"喂坏数据必须拒绝"的反面测试。

必须现在知道的三个事

紧急
1. 每次打开软件，后台都在抛一个"栈溢出"错误，但你看不见 我用浏览器实测：页面加载时 Vue 必抛 RangeError: Maximum call stack size exceeded（公式预览组件的响应式计算陷入无限递归）。好消息是它被 Vue 兜住了、软件照常能用（我截图确认界面完整，25 个按钮全在）。坏消息是：你项目里的"安全日志器"会把原始报错脱敏成 [QISI_LOG] {stage: application}——真话被洗成了废话。这就是一连串端到端测试挂掉的直接原因。 实测链路：app.js:5046 Vue 错误钩子 → qisi-secure-logger.js:64 脱敏 → 控制台只剩 {stage: application}（桩件绕过脱敏后还原真实报文）

做得好的地方（这些真的很扎实）

  • 安全理念落地了，不是口号。"不确定就放弃，绝不硬挂"这条原则，在宪法里写了，在代码里实现了，还有专门的"喂坏数据必须拒绝"测试看着它。这在同类项目里很少见。
  • 核心算法干净。答案／解析的匹配必须序号集合一致、不允许跳号重号重排、不允许靠"长得像"或关键词（三角形、向量、sin）猜——这几条硬规则写得很克制。
  • 防注入做得扎实。唯一有风险的富文本出口做了转义再渲染（禁止执行脚本），全项目未出现 eval、new Function。恶意 Word 文档灌不进脚本。
  • 依赖不再看天吃饭。把 Vue / KaTeX / pdf.js 等从公网 CDN 搬到本地，并加了完整性校验——断网也能开，这一步做对了（只差提交保存）。
  • 有一道真正动真格的门禁。verify-app-shell-architecture.js 用语法树解析真实校验 app.js 的行号、允许/禁止调用，不是摆设。
  • 事故复盘写得很专业。历史文档里有一份"会话丢失后的取证恢复审计"，如实记录了当时"状态文档说已验收、而提交记录证明没有"的矛盾，并做了纠正。有自我纠错的记录，说明这套体系是有羞耻心的。
