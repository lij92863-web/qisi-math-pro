# 奇思数学 Pro 本地运行与验证

## 启动与身份

双击项目中的 open-app.cmd，或使用现有桌面快捷方式。脚本核对本地服务实例，必要时后台启动，等待就绪后打开 http://127.0.0.1:3000/main.html。健康端点是 /api/health。遇到端口属于另一实例的提示时，先核实程序路径和服务身份，不批量结束所有 Node 进程。

题库在当前浏览器配置、当前站点来源的 IndexedDB 中。保持浏览器配置、主机名和端口一致；localhost 与 127.0.0.1、不同端口或无痕窗口可能看到另一份存储。看到空库先核对来源与浏览器配置，再做恢复操作。

停止服务应先确认启动它的终端或该项目的具体进程身份，完成保存和备份后停止该实例。本次建设只运行隔离验证服务，没有重启用户现有服务。

## 备份

在“题库与检索”选择备份文件夹或使用“下载完整备份”。现有完整备份包含题目、正式图片、模板、知识点、导入/合并记录、草稿批次、源记录和草稿图片等 11 张表及允许的偏好项；读取时验证归档结构和二进制内容。

确认下载文件可读取后另存一份到独立存储位置。源码 ZIP、Git 提交和题库数据备份用途不同；复制项目文件夹不能替代浏览器数据库备份。备份只保存允许的偏好，不包含秘密配置。

“已发起完整备份下载”表示浏览器已接到文件，仍需确认下载完成并保管好文件。记录“上次备份时间/校验报告”因本地空间不足而失败时，不再把已发起的有效下载误报成整次备份失败；这类记录异常会留在诊断警告中。真正的备份创建、归档校验或下载失败仍会报错。

## 恢复

先选择备份文件，检查恢复预览、记录数量和来源时间；选择安全备份文件夹并完成页面要求的确认，再恢复。界面会先保存当前数据的安全副本，并检查恢复前数据没有并发变化。

首次练习使用新建浏览器配置或隔离测试环境。清空→恢复演练不得在正式题库做。恢复后检查题目、图片、草稿来源和样例打印；遇到验证失败保留原包及错误，不能绕过校验强行导入。

恢复前的安全备份如果因空间不足或目录权限丢失而保存失败，先核对当前题库仍可见，处理空间或重新选择有权限的备份文件夹，再核对预览并明确点击恢复。程序不会替你自动重做恢复；不要通过清除浏览器数据、删除原库或修改备份ZIP来消除报错。两种写入失败和随后明确恢复已通过隔离UI测试，原库题图及11表计数保持，成功恢复前的安全包可读回原数据。

原生IndexedDB测试也覆盖了较早表或最后表写入时注入异常后的11表原子回滚。这些是受控故障注入结果，不是断电、磁盘损坏或全部浏览器故障的保证。遇到真实异常保留错误、源备份及恢复前安全包，核对题库与图片后再继续操作。

`local-run-artifacts/golden-baseline/`里的`full-source/source.zip`是开发源码恢复点，不能在“选择备份恢复”中用作题库数据包；只有界面下载的完整数据备份用于此入口。源码归档明确排除了生产浏览器题库和完整依赖环境。

## 开发验证

默认门禁：

    npm.cmd run verify:safe

当前真实顺序是 no-real-ai → 语法检查 → 全量 Node 测试 → write-boundary。全量测试会发现 batch mock、离线 golden 和隔离恢复用例；npm test 失败时最后一步不会执行，不能宣称整个门禁通过。

批量安全补充门禁：

    npm.cmd run verify:batch-safety

只读文件引用报告：

    node tools/inventory.cjs --out local-run-artifacts/code-inventory/<新目录>/report.json

报告同时生成Markdown，列出静态生产路径、仅诊断路径、缺少已知引用的候选和存疑文件。不会删除文件；动态加载、平台登记与实际入口差异、兼容和测试用途仍需核对。dead-candidate不能直接当删除名单，旧迁移脚本/回归对照仍引用的文件要保留。输出限于新的运行证据路径，拒绝覆盖已有报告或沿目录链接越界写入。

离线逐题回放、报告比较、标注协议和历史缓存诊断见 golden/README.md。回放没有 live 模式。真实识别需要单独明确材料、服务、预算及停止条件。

## 常见故障

| 现象 | 首先核对 |
|---|---|
| 打开后看不到旧题 | 浏览器配置、127.0.0.1/localhost、端口；不要先清缓存 |
| PDF 提示引擎未配置 | 查看失败原因和本地配置状态；不切换为猜测绑定 |
| 有答案候选却不能提交 | 字段是否已核对采纳、图片是否确认、范围问题是否处理、保存后是否重新确认 |
| 某题答案/解析留空 | 查看对应原页和证据，区分没有独立声明、冲突、序列/边界拒绝 |
| 备份无法恢复 | 保留原包，核对格式、完整性和预览；不手工改归档计数 |
| 验证报 spawn EPERM | 是子进程权限问题时申请运行现有测试的权限，不能修改断言掩盖 |

阶段结果、完整命令退出码和未解决事项见 ai 目录的对应任务报告。

## 打印检查

“只打印题目”“一份 PDF：题目后另起新页印答案”和题答分卷均有合成UI回归。正式使用时仍应查看生成PDF的全部页面，核对题号、选项字母、图片及题答分隔；网页预览正常不能证明纸面分页正常。含图选项被拆到多页的问题已通过局部打印样式修复，并用实际PDF读回和逐页渲染复验。证据PDF是合成短卷，不能当作真实试卷或数学质量认证。

若打印页提示“图片未能完整加载，请修复后重新生成”，本页打印按钮会保持禁用。回到原题核对图片是否存在、是否能正常显示，修复后重新生成预览；不要把缺图页当作准备完成。这项检查只控制应用自己的按钮，不影响浏览器菜单的打印命令，也不认证题目内容正确。
