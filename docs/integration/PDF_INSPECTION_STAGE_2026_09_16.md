# PDF deterministic-first 与可复核失败路径

本阶段已接入生产批量入口，尚不能代表真实视觉识别质量已验收。

## 架构与边界

- `qisi-pdf-inspection.js` 先读取 pdf.js 文本项、位置、字体大小、图像/矢量操作。
  将页分为可用文本、混合、扫描、读取失败。保留原始行和位置。
- `qisi-pdf-ingestion.js` 使用显式且连续题号契约；纯文本分块直接解析。
  混合页保留原页；视觉返回题号必须与原页文本证据一致，不能新增/重复/倒序。
- 真材料的公式有私用字符、脚标和跨行结构，不能把可提取文本等同于可靠数学文本。
  第 11 题文本项被分为 `1 1 .`，按标记结构恢复；第 6 题跨页选项明确待审。
- 支持字段继续经过既有 `PdfSupportAligner` 和 `PdfSupportControlledWrite`。
  不更改它们的已知坏例规则。缺显式答案不从详解结论回填。
- 源页文字无法证明身份的扫描页只保存待审证据，不采用模型自报题号。
- 每页至多一个请求；首个服务错误终止该文件其余请求；内容/模型/题号/角色散列缓存。
  PDF 读入、打开、逐页检查、渲染和识别均有超时；渲染最多 400 万像素、长边 2200。
  目前渲染逐页重新打开 PDF，尚有性能优化空间。
- app.js 只新增约 50 行编排、字段证据传递和批次报告保存。新路径不再进入末尾重复视觉修复。
- 审核页允许零可靠草稿但有待审原页，显示原始页面；不生成假题、不直接写正式库。

## 验证

- `node --test tests/pdf-ingestion.test.js tests/e2e/pdf-inspection-import.test.js`：7 项通过。
  覆盖纯文本真实 PDF 字节、混合页真实渲染、传输失败零假题、原页可见、跨页隔离、
  模型未知/重复/倒序号、缓存、字段答案拒绝、已知坏序列。
- `npm.cmd run verify:safe`：通过，日志 `artifacts/audit-baseline/astra-pdf-verify2.log`。
- `npm.cmd run verify:batch-safety`：通过。
- 真实简略 PDF + DOCX 答案走产品 UI：review、0 草稿、1 次被测试代理阻止的请求，
  没有实际付费调用。失败路径可复核，不代表识别成功。
- 三份真实 PDF 共 7 页均为 mixed；不是“无文本扫描件”。
