## 1. 为什么需要它（确定性路线已经到顶）

真实 PDF 的文本层在这三份材料上全部不可用：7 页全部被 inspection 判为
`mixed / unmapped-glyphs`（页面的字形没有 Unicode 映射，抽出来的"文字"不是文字）。这不是实现缺陷，
是文件本身的属性，确定性路线到此为止。判断依据见
`docs/integration/PDF_INSPECTION_STAGE_2026_09_16.md` 的逐页清单。

## 2. 建议的第一批（最小、可回退）

```text
文件     C:\Users\Administrator\Desktop\题目与答案\简略版题目（只有一页）.pdf（1 页，6 题）
页/区域  第 1 页整页 region [0, 0, 595.3, 841.9]（inspection 给出的仍是整页粒度）
模型     现行 PDF 视觉转录所用的同一个模型（qisi-pdf-ingestion 的 model 参数，当前为 getVisionModelsForMode 的第一个）
调用次数 1 次（单页单区域；若首调用失败，按既有规则终止该文件其余请求，不重试）
输入     该页的页面图（批次已保存的 ingestionSourcePages 原页图，JPEG）
输出     仅作为 unresolved-region 的证据：region 内识别出的文本/公式 → 进入 review 的待核对内容
```

预计成本：**1 次视觉调用**（单页 1191px 宽整页 JPEG，约 0.2–0.5 MP），按现行服务单价约人民币几分钱；
上限就是 1 次调用。若要一次把 7 页都做，则是 7 次调用，成本同比例。

## 3. 为什么确定性做不到

- 该页字体的字形没有 Unicode 映射（inspection 报告 `unmapped-glyphs`），文本层读不出可用的题号、
  选项和公式；
- 页面同时含文本、图形与公式，属于 `mixed` 页，无法只靠几何或词法规则恢复题目结构；
- 现有 OCR 引擎（本地 Paddle/PP-OCR 路线）只输出整页文本，不产出题目结构与公式归属，
  且这份材料是印刷体数学排版，拼装风险高于收益。

## 4. 结果如何被使用（不越界）

```text
允许：视觉结果作为 unresolved-region 的证据，进入 review 的待核对原页/待核对内容，由老师确认；
      视觉结果可以补足确定性证据缺失的字段，但必须在 fieldProvenance 里标明来源与置信度。
禁止：视觉结果直接生成正式题；覆盖已经确定的确定性证据；在答案/解析序列不可靠时按语义相似度挂载；
      绕过 fail-closed（PDF 支持仍只有 full / prefix / fail-closed 三种结果）。
```
