Environment gotchas learned the hard way:

- LibreOffice headless conversion needs an isolated profile:
  `soffice -env:UserInstallation=file:///<dir> --headless --convert-to pdf --outdir <dir> <file>`.
  The LibreOffice install on this machine had to be repaired from the MSI in `tmp/` (its `program`
  folder was empty, a broken upgrade).
- The browser harness blocks `**/api/ai/**` on purpose, and `https://` goes through
  `local-run-artifacts/r2-e2e-cdn-cache`; rebuild it with `node scripts/populate-e2e-cdn-cache.js`
  (pinned by `scripts/e2e-cdn-assets.lock.json`).
- `git commit -m "…$…"` breaks under PowerShell (the message gets mangled and git reports
  "did not match any file(s) known to git"). Keep commit messages free of `$`, backticks and quotes.
- Pushes sometimes fail with `schannel: failed to receive handshake` — retry once.
- `git status` may show `M app.js` while `git diff --stat` is empty; that is a line-ending artefact,
  the content equals HEAD. Verify with `git diff --stat`, not with status alone.
- The seal test compares `HEAD:app.js`, so it fails until the change is committed — that is expected.
  Whenever app.js changes, update `architecture/post-seal-approved-blobs.json` (git blob +
  content sha256) and the two ceilings in `tests/code-quality-boundaries.test.js` /
  `tests/app-shell-boundary.test.js`, then commit and re-run.

## 4. CLOSED DEFECT — wrong content on the wrong question (fixed 2026-09-16, fourth pass)

Kept here as the record of what the defect was and how it was closed. The full evidence is in
`docs/integration/HARDENING_INTEGRATION_LEDGER_2026_09_15.md` §13.

Three mechanisms, all measured on the real file, all fixed:

1. the paragraph reader's `w:t` alternative was unanchored, so `<w:tabs>`, `<w:tab w:val=…/>`,
   `<w:textAlignment …/>` and `<w:tcW …/>` were read as text elements and swallowed everything up to
   the next real `</w:t>` — that is where the 13–15 digit runs (`4071620147320`, `37611055556259`,
   `409130527749511`, the drawing's `<wp:posOffset>` pairs) and the lost `A. ` labels came from;
2. the flat splitter treated the mark sheet's `11. 12.` row as a question, so a bogus question 11
   carried the section header as its stem and question 1 was dropped by the no-jump-back filter;
3. option evidence was taken from the whole-document `pageText`, so the paper's first A.–D. run
   (question 7's options) was copied onto every question with no options of its own.

Result on `周二晚测.docx`: 12 drafts, question numbers 1..12, every stem and option set from its own
question, no shared option set, no leaked digit run. Six questions keep no options at all
(fail closed, manual review) because the paper holds those labels inside MathType equations.

Regressions: `tests/qisi-utils-question-evidence-scope.test.js` and
`tests/e2e/docx-question-scope.test.js` (the e2e one was run against `git show HEAD:app.js` and failed
there with `expected the paper's three questions, saw 2`).

`DOCX SILENT WRONG CONTENT > 0` case the acceptance forbids.

Captured table sequence during the same run narrows the moment:

The old hypothesis ("the same `parsed`/`options` object is attached to many items") turned out to be
right in substance — but the object came from the whole-document `pageText`, which
`extractOptionsFromCurrentBlockOnly` parsed as if it were the current question.

Where to look next (verified anchors):

Acceptance for the fix: on the real paper the question-number set must be 1..12 (or the absent ones

Status: met. The real file now gives 1..12 with each question's own stem and options; the regressions
