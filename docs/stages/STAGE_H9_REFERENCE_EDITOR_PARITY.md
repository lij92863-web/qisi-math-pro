# H9 — 参考编辑器能力与图片直接操作验收

状态：完成

## 目标与边界

H9 补齐讲义编辑器的题目级排版能力，重点是“直接拖动图片”和“拖拽四角缩放”。
本阶段只修改独立讲义入口、`qisi-handout-*` 模块、讲义测试与文档；没有修改
`app.js`、`main.html`、题库 schema、正式题目记录或 DOCX/PDF/批量识别链。

图片位置继续保存为结构化区域与对齐方式，图片尺寸继续保存为毫米或可用宽度百分比，
不保存浏览器绝对坐标。讲义中的局部编辑不回写正式题库。

## 已实现能力

- 选中题目图片后显示四个角的缩放手柄；拖动任一角均保持原始宽高比。
- 拖动图片可放入题干下方左/中/右、题干右侧、选项右侧、独立块左/中/右和行内区域。
- 指针移动阶段只在 `requestAnimationFrame` 中更新瞬时视觉状态；释放指针时才产生一次历史记录和一次自动保存。
- 支持图片上传、资源选择、替换、恢复、删除、排序、题注、对齐与多图布局。
- 表格保持结构化文本/LaTeX 数据，支持行列增删、单元格合并/拆分和列宽调整；HTML 与 Typst 共用同一数据模型。
- 答案、分析、解析位置支持题后、文末含题干、文末隐藏题干等明确策略；学生版在生成文档模型前物理移除教师字段。
- 支持非破坏性隐藏选项/图片、显示元数据、本地二维码、可逆 LaTeX 显示规范化，以及页眉页脚字体、字重、颜色、行高和区域偏移。
- 参考工具栏中的按钮均有真实处理程序或明确的不可用原因，不保留装饰性死按钮。

## 验收证据

- H9 模型测试覆盖图片交互、表格、二维码及 HTML/Typst 一致性。
- 真实 Chromium 工作流通过鼠标事件完成四角缩放、图片区域拖放、保存、重载、表格编辑、学生/教师 PDF 预览与下载。
- 50 道题场景下完成连续拖动，指针移动期间未启动正式 PDF 编译。
- 学生 PDF 未出现答案、分析、解析或教师备注；教师 PDF 保留对应内容。
- 本地二维码固定使用 Version 4-L、UTF-8 ECI，独立扫码验证解出 `TEX-H9-QR-TEST`；内容上限为 77 个 UTF-8 字节，超限失败关闭。
- 正式预览与下载使用同一 PDF 字节，HTML 快速预览与 Typst 正式输出消费相同的结构化布局决策。

## 明确限制

- 不提供任意像素坐标的桌面出版式布局，以避免跨屏幕、跨浏览器和 PDF 尺寸漂移。
- 不提供可能造成文字重叠的复杂自由环绕；使用经过验证的结构化图片区域。
- 二维码完全本地生成，不提供云短链、追踪或统计。
- “同步到题库”不得静默覆盖正式题目；需要进入可审阅的修订流程。
- OCR 仍属于既有受控边界，H9 没有新增或调用真实 OCR 链路。
